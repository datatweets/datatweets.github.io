Career Path

Data Engineer Career Path

A complete, free path toward a data engineering role — Python foundations, the techniques for processing data far larger than memory, distributed processing with Spark, containers and Kubernetes, and orchestration with Airflow, all on real open datasets. No cloud required.

Data engineers build the pipelines that move and shape data before anyone analyzes it. This path starts with solid Python, then Polars — a fast, expression-based DataFrame library for real local pipelines — before the craft of working with data too big for memory — measuring and shrinking it, processing it in chunks, parallelizing it, and structuring it for speed — then goes distributed with Apache Spark: DataFrames, Spark SQL, execution plans, and production ETL, all runnable on your own laptop. From there the pipeline becomes portable with Docker and Kubernetes, self-running with Apache Airflow, and event-driven with Apache Kafka — the same pipeline, containerized, orchestrated, scheduled, and streamed, entirely on your own machine. The path closes with analytics engineering: transforming landed data into tested, documented tables with dbt. Everything is verified on real, public datasets, across nine courses from first line of Python to a running, orchestrated, streamed, and transformed pipeline.

What you'll learn

  • Python programming from scratch
  • Fast, expression-based local DataFrames with Polars
  • Why data outgrows memory — and how to measure it
  • Memory-efficient NumPy and pandas at scale
  • Chunked and out-of-core processing with SQLite
  • Parallel processing across CPU cores
  • The data structures and indexes real pipelines rely on
  • Distributed processing with Apache Spark — DataFrames, Spark SQL, and production ETL
  • Containerizing and orchestrating a real pipeline with Docker and Kubernetes
  • Scheduling and monitoring pipelines with Apache Airflow — DAGs, sensors, hooks, and alerts
  • Event streaming with Apache Kafka — producers, consumers, Schema Registry, and Kafka Connect
  • Analytics engineering with dbt — models, tests, and documentation against a real warehouse

Phase 2 — Local Data Processing with Polars

A fast, modern DataFrame library built for exactly this path's next problem: real local data, real speed, before scaling out to Spark.

Beginner to Intermediate Polars for Python Developers Think in expressions instead of row-by-row loops: schemas, cleaning, joins, window functions, nested data, time series, lazy execution over CSV, JSON, Parquet, and SQLite, testing and debugging real pipelines, and a full local analytics pipeline capstone. Expression system & lazy execution &middot; Cleaning, joins & window functions &middot; Nested data & time series &middot; Parquet, SQLite & a local data lake 64 lessons 11 weeks Start module

Phase 3 — Scaling Data with Python

Where large-scale data engineering begins: handling data that's too big to fit in memory, in pure Python.

Beginner to Intermediate Scaling Python for Data Engineering Process data too big for memory using nothing but Python — measure and shrink it with dtypes, load only what you need, process in chunks, parallelize across cores, and build the data structures behind real pipelines — on the real NYC taxi dataset. Memory profiling & dtypes &middot; NumPy & pandas at scale &middot; Chunked & out-of-core processing &middot; Parallelism & data structures 36 lessons 8 weeks Start module

Phase 4 — Distributed Processing with Spark

The same data and the same engineering, at cluster shape — Spark in local mode, no cluster or cloud account needed.

Intermediate PySpark for Data Engineering Learn how Spark thinks — drivers, executors, lazy plans — then master DataFrames, Spark SQL, execution plans, partitions, shuffles, and caching, and finish with a production-shaped ETL with schemas, data-quality gates, and logging. SparkSession & lazy evaluation &middot; DataFrames & Spark SQL &middot; Execution plans & the shuffle &middot; Production ETL & data quality 36 lessons 8 weeks Start module

Phase 5 — Containers & Kubernetes

Make the pipeline portable: the same result on any machine, any server, any cluster.

Intermediate Docker & Kubernetes for Data Engineering Install Docker Desktop, learn images vs. containers, write and slim Dockerfiles, compose multi-service stacks, then orchestrate them for real on a local Kubernetes cluster with Kind — deployments, services, config, storage, and scheduled CronJobs. Phase 6 — Orchestration with Airflow

The pipeline becomes self-running: the same work from every earlier phase, scheduled, monitored, and recovering from failure on its own.

Intermediate Orchestrating Data Pipelines with Airflow Install Apache Airflow locally with Docker, author DAGs with the TaskFlow API and classic operators, add sensors, hooks, connections, tests, logs, alerts, and finish with a capstone that submits a PySpark job to Kubernetes from an Airflow DAG. DAGs & the TaskFlow API &middot; Sensors, hooks & connections &middot; Testing, logging & alerting &middot; PySpark-on-Kubernetes capstone 36 lessons 8 weeks Start module

Phase 7 — Event Streaming with Kafka

Process data the instant it happens, before it's ever written to a file — the real-time complement to every batch pipeline built so far.

Beginner to Advanced Apache Kafka for Data Engineers Install a real 3-broker Kafka cluster, write producers and consumers with reliable delivery, enforce data contracts with Schema Registry, move data with Kafka Connect, process streams with Faust and Spark Structured Streaming, orchestrate with Airflow, and close with a capstone streaming CityFlow's real trip data end to end. Producers, consumers & consumer groups &middot; Schema Registry & Kafka Connect &middot; Stream processing with Faust & Spark &middot; Cluster replication & a real capstone 56 lessons 10–12 weeks Start module

Phase 8 — Analytics Engineering with dbt

The last mile: turning landed, raw data into tested, documented tables an analyst can actually trust.

Intermediate to Advanced dbt for Data Engineers Install dbt Core against a real Postgres warehouse in Docker, build a branching DAG with ref() and source(), compare materializations, and prove the same models run unmodified against a second warehouse (DuckDB); declare sources with real freshness checks and a properly-named, two-table staging layer; test it with dbt's four generic tests, singular tests, and dbt-utils; build a zone dimension and a trip fact table as real marts, and reproduce this path's own zone-hour-report anchor entirely in dbt; write real Jinja macros to DRY up genuinely duplicated SQL, including dbt_utils's date_spine, generate_surrogate_key, and pivot; load a real 9.5-million-row multi-month history and convert CityFlow's own trip fact table to a real incremental materialization, all three of Postgres's supported strategies built and compared; snapshot CityFlow's own zone dimension with a real SCD Type 2 table, proving a real historical query survives a dimension change a plain mart silently loses; document every real model with description: fields, generate and serve an actual local docs site, read its own lineage graph, and declare a real exposure; write real dbt unit tests with given/expect fixtures against logic no data test could ever catch, confirmed by breaking that logic on purpose and watching the tests fail; add real dev/prod/Airflow targets isolated by schema and proven so at the Postgres object-ID level, select only what state-based comparison says actually changed, run a minimal CI gate on `dbt build`'s own exit code, and orchestrate the full staging-to-marts build with a genuinely scheduled Airflow DAG, watched, paused, and screenshotted succeeding — then closes with a capstone that drops and rebuilds the entire project from an empty Postgres schema, confirms full documentation coverage against the manifest, and reconciles a new Postgres-native report model to the exact anchor five earlier courses in this path already established, orchestrated end to end by a two-task Airflow DAG that checks its own result. Models, ref() & the DAG &middot; Staging, testing & marts &middot; Incremental models & snapshots &middot; Docs, unit tests & CI/CD 56 lessons 10–12 weeks Start module
