How to Audit Attention Weights with Token Occlusion in Python

A beginner-friendly audit of one transparent attention-pooling calculation. Compare raw weights with signed classifier contributions, remove each token and rerun the model, and learn which conclusions an attention heatmap cannot support by itself.

Mehdi Lotfinejad
August 15, 2026 · 11 min read

An attention heatmap can make a model look easy to explain: find the darkest cell and point to that token. The problem is that an attention weight answers only where one layer collected information. It does not say whether that information raised or lowered the final score.

To audit attention weights, record the normal model output, remove one token at a time, rerun the complete attention calculation, and compare every new logit with the original. Read those occlusion changes beside the attention weights and signed value contributions; a large weight alone cannot tell you whether a token supported or opposed the prediction.

This tutorial makes that distinction visible with one small NumPy calculation. We will audit the fictional message checkout latency normal payment failed recovered. Its numeric features were designed for teaching rather than learned from real incident data, so every intermediate result stays inspectable.

If query, key, value, and softmax are new terms, first read scaled dot-product attention in NumPy. Here, the main question is how to test an attention interpretation after those weights exist.

Setup for an Inspectable Attention Example

You need Python 3.11 or newer and basic knowledge of Python functions and NumPy arrays. You do not need a GPU, a trained Transformer, or calculus.

Create a virtual environment on macOS or Linux, activate it, and install the three packages used by the executed lesson:

On Windows PowerShell, activate the environment with .venv\Scripts\Activate.ps1. The artifact build used Python 3.13.2, NumPy 2.5.1, pandas 3.0.3, and Matplotlib 3.11.0.

Download synthetic_incident_token_vectors.csv and save it beside your Python file. This original synthetic dataset is released under CC0-1.0. Synthetic means that the six tokens and all numeric features were created for this lesson. They do not describe a person, organization, production service, or trained model.

Load the file and inspect the complete table before calculating attention:

Each row is one token position. The three key_ columns describe how a token can match an incident-summary query. The two value_ columns carry information about disruption and recovery after a match is made. These feature names are teaching labels. Features inside a trained neural network usually do not have such direct meanings.

Understanding the Three Questions Behind an Attention Map

The audit compares three quantities. They answer different questions:

  1. An attention weight asks, “What coefficient multiplies this token’s value in the pooled context?” It is nonnegative, and all token weights sum to 1.
  2. A signed contribution asks, “Did that weighted value push the chosen class score up or down?” It can be positive or negative.
  3. A token-occlusion change asks, “How much does the output change when this token is removed and attention is recalculated?” Occlusion means hiding one part of the input for a controlled test.

The output before the sigmoid function is called a logit. In this lesson, a positive logit change means that removing the token lowered the escalation logit, so the token supported escalation. A negative change means that removal raised the logit, so the token opposed escalation.

The difference matters because an attention pool has two stages:

Keys affect the weights, but values carry the information sent downstream. The classifier then decides which directions in the context support its output. A weight shows the size of a route, not the sign or meaning of what traveled along it.

This lesson uses one fixed summary query with three features and one fixed classifier with two weights:

The query asks for an incident summary. The classifier gives positive weight to disruption and negative weight to recovery. These constants make the output easy to trace; they are not presented as useful production parameters.

Calculate the Baseline Weights and Prediction

We first need a baseline: the unchanged result that every occlusion run will be compared with. The next two functions calculate stable softmax, scaled query-key scores, the weighted context, and a binary probability.

Subtracting the largest score before exponentiation prevents overflow without changing the softmax ratios. NumPy’s current documentation defines the shape rules used by the @ matrix-multiplication operator and the element-wise behavior of np.exp.

The division by the square root of the key width is the scaling step in scaled dot-product attention. The Transformer paper introduced this calculation for learned queries, keys, and values. Our example uses one summary query, so it produces one weight per token rather than a square token-by-token matrix.

Run the function and place the scores and weights beside the token names:

The weights total 1, apart from normal floating-point rounding. failed receives the largest share, 24.6%, while recovered receives 20.4%. The final probability is 48.4%, just below the hypothetical 50% threshold used to illustrate an escalation decision.

That output does not yet prove that failed raised the probability or that recovered lowered it. The weight column contains no negative numbers and has not used the classifier direction.

Add the Direction of the Classifier

The classifier logit is a weighted sum of the two context features plus its bias. Because this classifier is linear, we can distribute that calculation back across tokens without changing the result.

First, multiply every value vector by the classifier weights. This value_alignment is positive when the value points toward escalation and negative when it points away. Then multiply that alignment by the token’s attention weight:

Now the direction is visible. failed contributes about +0.663 to the logit, while recovered contributes about -0.561. The token normal also pushes against escalation even though its weight, 15.2%, is larger than the weights for three other tokens.

Adding all six contributions and the -0.1 bias reproduces the baseline logit of -0.0641. This exact decomposition works because the downstream classifier in our controlled example is linear. A deeper nonlinear network may not allow the score to be divided this neatly, which is why the next behavior test is more widely useful.

Remove One Token and Rerun the Complete Calculation

Token occlusion tests model behavior under a controlled input change. For every position, remove its key and value together, rerun softmax over the five remaining positions, and compare the new logit with the baseline.

It is important to rerun the whole function. Deleting a token changes the softmax denominator, so all remaining attention weights are normalized again. Simply setting one existing weight to zero would leave an invalid row that no longer sums to 1.

Read the final column first. Removing failed lowers the logit by 0.867, so failed is the strongest supporter of escalation in this test. Removing recovered raises the logit: the reported change is -0.714, and the probability rises from 48.4% to 65.7%. Removing normal also raises the probability, but by less.

The test supports a narrow conclusion: for this specific input and model, those removals changed the score in those directions. It does not prove that the words have the same effect in every message. In a real language model, removing a token also shortens the input, may shift later positions, can change interactions among the remaining tokens, and may create unnatural text.

The executed chart places all three views on the same token axis:

Start in the left panel: every attention bar is positive. Move to the center and right panels to see direction. The center panel shows an exact decomposition for this linear classifier. The right panel shows a behavior check that recalculates attention after removal. Their values differ because occlusion also redistributes weight among the remaining tokens, but both identify failed as supportive and recovered as opposing.

You can download the full executed attention_audit_results.csv to inspect all values at nine decimal places.

Prove That Weights Do Not Contain the Values

A controlled value swap exposes the limit directly. Keep every query and key unchanged, but exchange the value vectors for failed and recovered. The attention weights must remain identical because the weight calculation never reads the values.

The weight vector is exactly unchanged, but the probability moves from 48.4% to 42.8%. The same attention coefficients now multiply different value vectors, so the classifier receives different information.

Treat this as a test of the attention equation, not as a normal edit to a language model. In many trained architectures, queries, keys, and values are different projections of the same hidden state. Editing a real token can therefore change all three. The controlled swap is useful because it isolates one fact: attention weights depend on queries and keys, while the output also depends on values and later layers.

Common Mistakes and Safer Interpretations

Calling the largest weight the “most important token.” State the layer, input, head, and question instead. A safer sentence is: “This attention pool assigned its largest weight to failed for this input.” Then use contribution or perturbation evidence before claiming an effect on the output.

Ignoring the sign of downstream processing. Softmax weights are nonnegative, but value features and later model weights can be negative. A large attention route can carry evidence away from the selected class.

Zeroing a weight without normalizing again. That does not represent the model after token removal. Delete or mask the token before softmax, then run the complete forward calculation.

Removing a key but keeping its value. Keys and values are aligned by position. Remove both rows together, or a remaining key may point to the wrong value.

Comparing probabilities only. The sigmoid function compresses large positive and negative logits. Record the logit change for a clearer score comparison, then report probability when it helps explain a threshold crossing.

Treating occlusion as causal proof. Occlusion measures model behavior under a chosen input change; it does not establish cause and effect in the world. The shortened input may be unnatural, correlated tokens can share information, and attention can move to a substitute token. Use several tests and describe the intervention precisely.

Averaging attention heads too early. Different heads can use different value projections. If you audit a multi-head model, preserve the head axis first. The DataTweets guide to multi-head attention and padding masks in PyTorch shows how to request separate per-head weights.

Forgetting evaluation mode. In a framework model, disable training-time randomness before comparing baseline and occluded runs. Use the framework’s evaluation and no-gradient settings, and keep every condition except the removed token fixed.

Recap: Weights Are One Part of the Path

An attention weight is the coefficient that an attention operation uses to mix one value into its context. It does not include the value’s direction relative to a class, the effect of later layers, or the changes that occur when an input is removed.

The audit used three views for one message:

  1. Raw attention weights showed that failed and recovered received the largest shares.
  2. Signed contributions showed that failed pushed toward escalation while recovered and normal pushed away.
  3. Token occlusion confirmed those directions after recalculating the complete pool.

Keep the durable workflow: record a baseline, define the output being explained, perturb one token at a time, rerun the model, and compare those changes with the attention map. Agreement can support a limited interpretation. Disagreement is useful evidence that the heatmap alone is not the explanation.
