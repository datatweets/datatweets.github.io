How to Build Hybrid Search for RAG with RRF Using Python

Build two transparent retrieval channels, combine their rankings with Reciprocal Rank Fusion, and evaluate exact-term and paraphrase retrieval before adding a language model.

Mehdi Lotfinejad
July 30, 2026 · 11 min read

A retriever can miss a useful document in two opposite ways. Keyword search may not connect “solid yellow” with “steady amber.” Semantic search may understand the topic but overlook a precise term such as idempotency key. A retrieval-augmented generation system, or RAG system, cannot ground an answer in evidence that its retriever fails to return.

To build hybrid search for RAG in Python, rank the same documents once with TF-IDF keyword similarity and once with sentence-embedding similarity. For each document, add 1 / (60 + rank) from both ranked lists, then sort these totals. This Reciprocal Rank Fusion (RRF) step combines exact-term and meaning-based retrieval without comparing incompatible raw scores.

We will build that process on a small fictional sensor-support knowledge base. We will not use a language model to generate answers. Leaving generation out makes every retrieval decision visible and testable.

How Hybrid Ranking Works

Lexical search looks for shared words and phrases. We use TF-IDF, which gives more weight to terms that occur in fewer documents. This channel is useful for codes, field names, and exact product terms.

Semantic search looks for related meaning. A sentence-embedding model converts each query and document into a fixed-length numeric vector called an embedding. Similar directions in the vector space should represent related text, even when the words differ.

The scores from these channels do not share a scale or distribution. A TF-IDF cosine score of 0.30 is not equivalent to an embedding cosine score of 0.30. Adding the raw numbers can let one channel dominate simply because of how its scores are distributed.

Reciprocal Rank Fusion, or RRF, avoids that scale problem by using positions:

Rank 1 means first place. The constant k controls how quickly contributions decrease down each list. A larger value gives lower-ranked documents more influence relative to the first few results. We set it to 60, the default value documented in the current Elasticsearch RRF reference. That reference also explains how a rank window limits the results included from each channel.

For this 12-document lesson, the rank window contains all 12 documents. In a large system, each retriever normally contributes only its top results. A larger window gives more candidates a small vote, but it also increases fusion work.

Build the Exact-Term Channel with TF-IDF

Each row represents one query, and each column represents one knowledge-base document. ngram_range=(1, 2) uses single words and adjacent two-word phrases. sublinear_tf=True replaces a term’s raw frequency with 1 + log(frequency), so repeated occurrences add less weight.

The scikit-learn TfidfVectorizer documentation defines the transformation. Its cosine-similarity guide explains why cosine similarity is a common comparison for TF-IDF document vectors.

Fit the vectorizer only on the document collection. If you fit a separate vectorizer on incoming queries, the query and document matrices can have different vocabularies and cannot be compared correctly.

Add Meaning with Sentence Embeddings

The second channel uses sentence-transformers/all-MiniLM-L6-v2. Its official model card describes a 384-dimensional English model for sentence and short-paragraph similarity and lists the Apache-2.0 license.

Load the model on the CPU. Use encode_document() for the knowledge base and encode_query() for questions:

The first shape means that each of the 12 documents has 384 values. The second shape matches the keyword score matrix: 12 queries by 12 documents.

This model is intended for English sentences and short paragraphs. Its model card states that inputs longer than 256 word pieces are truncated, so long passages can silently lose text at the end. Check your document lengths, languages, model license, and data rules before applying it to a real knowledge base.

Fuse Positions with RRF

RRF needs ranks rather than raw scores. The next helper sorts high scores first and fills a matrix with one-based positions:

Negating the scores makes the largest value appear first when argsort() sorts in ascending order. A stable sort preserves the original column order when documents have equal scores. Here, the columns follow the knowledge-base row order, so exact ties resolve consistently across runs.

Now add a reciprocal contribution from both lists. rank_window is 12 here because the teaching collection contains only 12 documents:

Because the function adds one contribution from each rank matrix, it gives the two channels equal weight. This implementation does not learn weights, and it does not need the two score distributions to match. That simplicity makes it a useful baseline, but it does not prove that equal weighting is best for every application.

Read One Fusion Decision by Hand

Start with Q01: Which fields form the idempotency key? TF-IDF puts the expected document first because that exact technical phrase occurs in KB-106. The embedding channel puts KB-106 fifth and prefers a more general passage about stored readings.

Print the top three fused rows with both input ranks:

KB-106 wins because it receives contributions from keyword rank 1 and semantic rank 5. KB-102 receives a contribution from semantic rank 1 but only keyword rank 6. The difference is small because a rank constant of 60 keeps adjacent rank contributions close together.

This is also why an RRF score is not a probability or a cosine score. 0.031778 means only “the sum of this document’s reciprocal rank contributions under these settings.”

Measure All Queries, Not One Good Example

For each method, find the rank of the labeled expected document. Hit@1 is the share of queries with the expected document first. Hit@3 is the share with it anywhere in the first three results. Mean reciprocal rank, or MRR, averages 1 / rank, so earlier relevant results receive more credit.

Twelve author-written questions are enough to inspect the algorithm. They are not enough to choose a production retriever. For a stronger experiment, label real query patterns, keep a holdout set, and inspect every case where methods disagree. The RAG chunk-size testing tutorial shows how to separate development questions from a final holdout.

What Can Go Wrong

Adding raw TF-IDF and embedding scores. Their numeric ranges have different meanings. Fuse ranks, or calibrate and validate a score-normalization method before using a weighted sum.

Using zero-based array positions in the formula. RRF ranks start at 1. Passing 0 for the first result makes its contribution too large and no longer matches the documented equation.

Using a rank window that is too small. A useful document outside one channel’s window receives no vote from that channel. Increase the window, measure latency, and inspect whether new candidates improve labeled retrieval.

Treating RRF as a guarantee. Two retrievers can agree on the wrong document. Fusion can also lower a document that only one channel finds. Keep per-query labels and compare methods after changes.

Fitting TF-IDF on queries. Fit on the document corpus and call transform() for queries. Fitting jointly on documents and evaluation queries leaks query wording into the vocabulary and inverse-document-frequency values. Fitting a separate query vectorizer creates a feature space that is incompatible with the document matrix.

Using incompatible embedding settings. Use the same model version and its matching query and document methods. Save the model name, normalization choice, and index version with the results.

Ignoring exact ties. A query with no vocabulary overlap can give many TF-IDF documents a score of zero. Use a stable tie rule, record top scores, and do not interpret an arbitrary first row as strong evidence.

Assuming English results transfer to other languages. Use a documented multilingual model and labeled queries for each intended language. Translation quality and domain terms can change rankings.

Sending every top result to a language model. Hybrid search improves candidate ranking; it does not establish that a question is answerable. Add relevance checks, access filters, citations, and an abstention path. The RAG answer evaluation tutorial covers those later evidence checks.

What You Learned

Hybrid retrieval gives exact wording and related meaning separate ways to find evidence. TF-IDF is transparent and strong on identifiers and technical phrases. Sentence embeddings can connect paraphrases. RRF combines their rank positions without treating their raw scores as comparable.

In this executed example, keyword search reached 66.7% Hit@1, semantic search reached 91.7%, and RRF reached 100% on 12 synthetic queries. The percentages are specific to this teaching dataset. The reusable lesson is the workflow: create labels, run channels separately, fuse one-based ranks, inspect disagreements, and measure again whenever the documents, model, or settings change.

Before adding answer generation, replace this small knowledge base with a versioned sample from your own domain. Include exact codes, short questions, paraphrases, near-duplicate documents, unsupported questions, and every language you plan to serve. Retrieval should earn trust through visible evidence before its results become model context.
