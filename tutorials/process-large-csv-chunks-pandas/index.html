How to Process a Large CSV in Chunks with pandas Safely

Read a large CSV in fixed-size pandas chunks, reduce each chunk to small additive totals, merge those totals by group, and calculate exact rates and means without rebuilding the full DataFrame.

Mehdi Lotfinejad
August 2, 2026 · 11 min read

A delivery export is too large for one pandas DataFrame, but the question is small: which distribution hub has the highest late-dispatch rate? Reading the file in pieces avoids holding every row in memory at once. However, the calculation can still produce a wrong answer if those pieces are combined incorrectly.

To process a large CSV in pandas, pass a row count to pd.read_csv(..., chunksize=...), reduce every chunk to additive values such as sums and counts, and add those partial results by group. Calculate means and rates only after all chunks are merged; do not average the chunk averages.

This tutorial builds that pattern with 180,000 fictional dispatch records. The file is small enough for us to verify once with a full read, but the main analysis keeps at most 13,000 source rows in a DataFrame at one time.

How Chunk-and-Combine Works

A chunk is a limited block of consecutive rows from a file. Setting chunksize=13_000 makes read_csv return an iterator instead of one complete DataFrame. An iterator supplies the next chunk when the loop requests it.

The calculation has three stages:

The retained state is one short table with a row for each hub. The input can grow from thousands to millions of rows without making that table longer, as long as the number of hubs stays small.

The key is to keep additive values. A value is additive when partial results can be summed without changing its meaning. Row counts, completed counts, late counts, package totals, and total delay minutes are additive. A mean is not.

The value 27.50 gives the one-row chunk the same weight as the two-row chunk. The correct mean is (6 + 14 + 45) / 3, or 21.67. This is why our large-file analysis will carry both delay_total_minutes and completed_dispatches across chunk boundaries.

Setup and the Fictional Dispatch Data

You need Python 3.11 or later and basic experience running a Python file or notebook cell. A pandas DataFrame is a table with named columns. You should also recognize a loop and a function, but you do not need previous large-data experience.

Create a virtual environment and install pandas and Matplotlib. pandas performs the chunked analysis, while Matplotlib creates the final chart. NumPy is installed as a pandas dependency and is used only by the reproducible data builder.

On Windows PowerShell, activate the environment with .venv\Scripts\Activate.ps1. The executed outputs use Python 3.13.2, pandas 3.0.3, NumPy 2.5.1, and Matplotlib 3.11.0.

Download synthetic_dispatch_log.csv and save it beside your Python file. This original synthetic dataset is released under CC0-1.0. A fixed random seed created all 180,000 rows. The hub names, dispatches, times, service levels, package counts, statuses, and delays are fictional and do not describe a real operation or person.

Inspect five rows before designing the aggregation. nrows=5 reads only the preview, so this check remains small.

One row represents one dispatch, not one package. packages says how many packages belong to that dispatch. A completed row has a whole-number delay_minutes value. A cancelled row leaves that field empty because it never departed.

The analysis needs only four of the seven columns. It will count a completed dispatch as late when its delay is greater than 15 minutes.

Read Only the Columns the Calculation Needs

The next step creates the chunk reader. usecols skips identifiers, timestamps, and service levels because the grouped result does not need them. Explicit dtype values also prevent pandas from choosing wider types for every chunk.

Int16 begins with a capital letter because it is pandas’ nullable integer type. It can hold both whole numbers and missing values. A plain NumPy int16 column cannot represent the empty delays on cancelled rows.

The current pandas read_csv reference states that chunksize returns a TextFileReader for iteration. The same page makes an important distinction: low_memory=True may parse internally in pieces, but it still returns one complete DataFrame. Use chunksize when your own code must receive separate DataFrames.

Reading fewer columns and choosing compact types also helps each chunk. The pandas memory-usage tutorial explains usecols, categorical text, and numeric widths in more detail.

What Chunking Cannot Calculate This Way

The pattern is exact for calculations that can be represented by small mergeable state. Sums, counts, minimums, and maximums are direct examples. Means and rates also work when you retain their component sums and counts.

Other questions need more care:

  • An exact median or arbitrary percentile may require retaining many values, sorting externally, or using an algorithm with a stated approximation error.
  • A global duplicate-ID check needs memory for seen IDs or an on-disk system that can enforce uniqueness.
  • A join between two large unsorted CSV files needs coordination beyond one independent chunk at a time.
  • A groupby with millions of unique keys can make the running result itself too large for memory.

In those cases, move the coordination to a suitable SQL database or another out-of-core system. Chunking changes how rows enter pandas; it does not make every operation memory-bounded.

Common Mistakes and Troubleshooting

Averaging chunk averages. Retain the sum and valid count for every group. Divide once after merging all chunks. The same warning applies to percentages: add numerators and denominators, not percentages.

Collecting chunks with pd.concat. Concatenating every piece rebuilds the full DataFrame and removes the memory benefit. Reduce each chunk and discard its source rows before requesting the next chunk.

Using low_memory=True as if it were chunksize. low_memory controls internal parsing behavior. It does not make read_csv return separate DataFrames. Set chunksize explicitly.

Selecting a chunk size by row count alone. Wide text rows use more memory than short numeric rows. Start conservatively, inspect chunk.memory_usage(deep=True).sum(), and measure the process under a realistic memory limit.

Letting each chunk infer its own types. A column may look numeric in early chunks and contain text later. Set known dtype values and decide how invalid rows should be handled instead of silently changing types.

Treating missing delay as zero. This tutorial uses zero only inside delay_total and excludes cancelled rows from the completed count. Filling the public delay column with zero would claim that a cancelled dispatch departed on time.

Forgetting that the final chunk can be shorter. Never multiply chunks_processed * chunksize to get the row count. Add len(chunk) inside the loop.

Seeing an out-of-memory error anyway. Check for retained source chunks, growing lists, large temporary copies, or a running group table with too many unique keys. Reduce the chunk size only after removing accidental full-data state.

Recap: Keep the State Smaller Than the File

Chunked CSV processing is not mainly about the loop. It is about choosing a result that can be carried forward in a small form.

For this dispatch question, every chunk becomes five totals per hub. Matching hub rows are added, and only then are mean delay and late rate calculated. The executed analysis processes 180,000 rows in 14 chunks, retains no list of source chunks, and matches the full-read result exactly.

Use the same design question on your own file: “What is the smallest state I need from earlier rows?” If the answer is a few sums, counts, minimums, or maximums per group, pandas chunking can be a clear single-machine solution. If the state grows with nearly every row, change the algorithm or move the coordination to disk before increasing the chunk size.
