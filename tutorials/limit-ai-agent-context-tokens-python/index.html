How to Limit AI Agent Context Size with a Python Budget

Build a provider-neutral context manager for a fictional cold-storage audit agent. Replace an ever-growing event history with a validated checkpoint and four recent events, measure both compact JSON payloads, and reject oversized requests before a model call.

Mehdi Lotfinejad
August 5, 2026 · 12 min read

An agent that sends its complete history on every step repeats every old tool result in every new request. The first few calls look small. Later requests grow, and the unfinished work becomes harder to identify inside the repeated history.

To limit AI agent context growth in Python, keep stable instructions once, replace old events with a structured checkpoint, retain only a short window of recent events, and measure the serialized request before each model call. Reject or rebuild any request above your application budget, then verify actual token usage from your model provider because bytes and tokens are different units.

This tutorial builds that boundary without an API key. A fictional cold-storage audit gives us 29 reproducible events, including flags that open and later resolve. We will compare the full history with a checkpoint plus four recent events, then verify that replaying the complete event history produces the same checkpoint.

Prerequisites and Reproducible Setup

You need Python 3.11 or newer and basic knowledge of dictionaries, lists, and functions. A context is the information sent to a model for one request. An agent loop repeats a cycle: choose an action, receive a result, update state, and choose again.

Create and activate a virtual environment, then install the two packages used for the table and chart:

On Windows PowerShell, use .venv\Scripts\Activate.ps1 for the activation command. The executed artifacts used Python 3.13.2, pandas 3.0.3, and Matplotlib 3.11.0.

Download synthetic_cold_storage_agent_events.csv and save it beside your Python file. The dataset is original synthetic teaching data released under CC0-1.0. Its 24 container IDs, readings, flags, and follow-up notes are fictional. They do not describe real equipment, products, users, or organizations.

No model call is needed. This is deliberate: context construction is application logic, so you should be able to test it without network access or variable model output. If you are new to the runtime around model tool calls, first read Build a Safe AI Agent Loop in Python.

Understanding What Must Last and What Just Happened

An agent does not need every old sentence in every future request. It needs the information that can still change a decision.

Use three layers:

  1. Stable instructions define the role, safety boundary, and output contract.
  2. A checkpoint records durable task state, such as totals and unresolved flags.
  3. A recent window preserves the last few raw events so the model can understand the immediate sequence.

The checkpoint is not a prose summary. It is structured JSON with named fields that Python updates and validates. This matters because a sentence such as “most containers passed and one still needs attention” hides the exact count and identifier. A field such as {"container_id": "COLD-023", "issue_code": "SEAL_REVIEW"} does not.

We will measure each serialized context in UTF-8 bytes. Serialization converts Python objects into text for storage or transmission. A byte budget is provider-neutral and available before a request leaves your program. It is not a token count: tokenizers divide text differently, and an API may add message wrappers, tool definitions, or other fields. Use this byte measure as a deterministic preflight gate, then compare it with provider-reported input tokens in production.

The 1,900-byte threshold in this lesson is a teaching limit chosen for this payload. It is not a model context-window limit and not a general default.

The full-history payload will keep every rendered event. The bounded payload will replace older event text with the checkpoint and a short queue. A deque is a double-ended queue; with maxlen=4, appending a fifth item removes the oldest automatically. The behavior is documented in Python’s collections.deque reference.

Four is not a universal window size. It is a policy for this trace, where the checkpoint owns durable facts and recent events provide local sequence. If an agent must compare observations separated by many steps, preserve the comparison result in the checkpoint or retrieve the relevant record by identifier.

Add a Gate Instead of Hoping the Context Fits

Measurement becomes useful when it controls execution. Place the gate immediately before the model call:

A real application needs a second, provider-aware limit. Use the exact model tokenizer when it is available, or read the input-token usage returned by the API and store it with the request version. OpenAI’s official tiktoken repository documents its model tokenizers, but an encoding may need its data files on first use. Pin the package and encoding, prepare that cache in your deployment, and test the path without network access if your runtime is offline.

Do not set the application threshold equal to a model’s advertised maximum. Leave room for tool schemas, message framing, the model’s output, and any provider fields your local payload does not count. A byte gate is the early warning; provider token accounting is the final evidence.

What Can Go Wrong with a Context Budget

The checkpoint is free-form prose. Important identifiers and counts can disappear during rewriting. Keep decision-critical state in typed fields, and validate the transition that changes each field.

Old events leave the request before state updates. Apply and validate an event first. Only then may it leave the recent window. Otherwise, the agent can forget a flag that was never copied into durable state.

A resolution can close any issue. Require the container and issue code to match an open record. The build raises ValueError when a follow-up refers to an unknown or different flag.

Missing values become truthy issues. pandas uses NaN for many missing cells, and bool(NaN) is true. Normalize missing values before branching on text fields.

The window size is copied without testing. Four recent events fit this audit contract. Label realistic tasks, vary the window, and test whether later actions still have the evidence they need.

Byte reduction is reported as token savings. UTF-8 bytes and model tokens are related text-size measures, not interchangeable units. Name the unit in column names, charts, logs, and claims.

Only the final request is measured. A loop repeats context many times. Store both per-request and cumulative measurements so one small last call cannot hide earlier waste.

The context shrinks but behavior is never checked. Size is only one requirement. Run scenario tests that compare full and bounded context on next-action accuracy, unresolved-item recall, tool arguments, and stop decisions before changing production traffic.

Private data is copied into the checkpoint. Compact does not mean safe. Store the smallest decision-relevant fields, redact secrets and personal data, restrict logs, and define a retention period.

Recap: Keep the Contract, Change the Budget

The reusable idea is not “keep four messages.” It is to assign every piece of context a job:

  • stable instructions hold rules that do not change during the run;
  • a validated checkpoint holds facts that must survive;
  • a recent window holds local sequence details; and
  • a preflight gate stops oversized requests before they leave your program.

For this synthetic audit, the full-history context crossed the 1,900-byte teaching limit at step 11 and reached 4,299 bytes. The structured route never exceeded 1,220 bytes, retained the one unresolved COLD-023 flag, and reduced cumulative serialized context from 71,484 to 32,402 bytes.

Those numbers belong to this JSON format and dataset. For your agent, define the state contract first, replay labeled traces to verify the state, test whether the bounded context preserves required decisions, and then choose byte and token limits for the request shape and model you operate. The durable habit is simple: update state, keep recent evidence, measure, then call.
