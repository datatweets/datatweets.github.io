How to Read XGBoost Trees and Trace Predictions in Python

A beginner-friendly guide to reading XGBoost's text and table tree dumps, following one delivery row through every tree, and verifying the additive prediction against the model's raw output.

Mehdi Lotfinejad
July 29, 2026 · 10 min read

An XGBoost prediction can look like one unexplained number. Inside the model, however, each tree sends the row through a short set of questions and adds one leaf value to a running score. Reading that path is a practical way to check what the fitted model actually calculated.

To read an XGBoost tree in Python, call model.get_booster().get_dump() for readable split rules or trees_to_dataframe() for a table. For one prediction, call Booster.predict(..., pred_leaf=True) to get the reached leaf in each tree, look up those leaf values, and add them to the model’s base score; verify the total with output_margin=True.

This tutorial audits a small regression model that estimates fictional courier delivery time. You will read its first tree, follow one delivery through all five trees, and reproduce its 82.40-minute prediction without Graphviz. If fitting and testing a model are new ideas, begin with your first machine learning model.

Setup before you open a tree dump

You need Python 3.11 or newer and basic knowledge of table rows and columns. A regression model predicts a number, such as delivery minutes. You do not need to know tree mathematics or install Graphviz.

Create a virtual environment and install the five libraries used in the executed lesson:

On Windows PowerShell, activate the environment with .venv\Scripts\Activate.ps1. The executed build used Python 3.13.2, NumPy 2.5.1, pandas 3.0.3, scikit-learn 1.9.0, XGBoost 3.3.0, and Matplotlib 3.11.0.

Download courier_delivery_stops.csv and save it beside your Python file. It is an original synthetic dataset released under CC0-1.0. Synthetic means the records were generated by code. All 800 delivery IDs, conditions, and times are fictional; they do not measure a real delivery service.

Load the file and inspect four rows before choosing model inputs:

Each row represents one completed stop. The five numeric features are measurements available before the delivery finishes. delivery_minutes is the target that the model learns to predict. delivery_id is only a label, so it must not enter the model.

How one boosted tree works in the ensemble

A decision tree routes a row from a starting root node through one or more split questions. A node is one point in that route. A leaf is an ending node that returns a number.

XGBoost uses boosting, so it does not rely on one tree. It starts from a base score, then adds the leaf reached in tree 0, the leaf reached in tree 1, and so on:

The leaf values in the dump are corrections, not complete delivery predictions. A positive value raises the running prediction; a negative value lowers it. The fitted tree already reflects the configured learning rate, so do not multiply a dumped leaf by the learning rate again.

For this lesson, the objective is reg:squarederror. Its output uses an identity transformation, so the raw margin—the score before an objective-specific transformation—is also the predicted number of minutes. Binary classification is different: a logistic objective transforms its raw margin into a value between zero and one.

The current XGBoost prediction guide documents output_margin and pred_leaf, including their output shapes. The guide is useful because classification, multiclass models, and parallel trees can produce shapes that differ from this simple regression example.

Fit a model that remains inspectable

Name the feature columns explicitly, then reserve 200 rows for testing. The test rows do not fit any tree:

This random split is suitable for independent fictional stops from one stable process. Repeated stops from the same real courier or route may need a group-aware split. If the goal is to predict later deliveries from earlier records, use a chronological split instead.

Now fit only five trees, each limited to two split levels. A production model may need more trees, but a small ensemble lets us inspect every correction. The explicit base score of 20 minutes makes the final addition easy to verify:

These are teaching settings, not recommended defaults. In particular, the model is intentionally small and was not tuned. Passing a pandas DataFrame keeps the readable feature names in the fitted booster.

Check that the model learned a useful signal before interpreting it. Compare its test mean absolute error with a baseline that always predicts the training target’s mean. Mean absolute error (MAE) is the average absolute distance between the actual and predicted time; lower is better.

The five-tree model reduces MAE by about 10.71 minutes on these 200 synthetic test rows. That result gives the audit a meaningful fitted model, but it does not estimate performance for a real courier system.

Turn the first tree into readable rules

The scikit-learn wrapper holds an XGBoost Booster, which supplies lower-level inspection methods. Confirm the feature names and the number of dumped trees first:

get_dump() returns one string per tree. According to the current official Python API, it supports text, JSON, and DOT output. A dump is for interpretation or visualization; the model I/O guide says to use save_model() instead when you need a model that XGBoost can load again.

Print tree 0. with_stats=True adds gain and cover:

Read node 0 from left to right. If distance_km < 8.76, the row follows yes=1; otherwise it follows no=2. A missing distance also follows node 2 because missing=2. At node 2, traffic below 7.23 reaches leaf 5, while traffic at or above 7.23 reaches leaf 6 and adds 41.49 minutes.

gain measures the improvement in the training objective from making a split. cover is the sum of second-order gradient values at a node. It equals the row count in this unweighted squared-error example, but that equality does not hold for every objective or weighting scheme. Treat cover as an XGBoost statistic, not a universal row counter.

The table prefixes child IDs with the tree number, so 0-6 means node 6 in tree 0. Filter by both Tree and Node when looking up a leaf because another tree can also have a node numbered 6.

Follow one delivery through every tree

Use one untouched row, STOP-0277, for a post-training audit. First display its inputs and known outcome:

Its distance is not below 8.76, so tree 0 moves from node 0 to node 2. Its traffic index is not below 7.23, so the next step reaches leaf 6. The first correction is therefore +41.49 minutes.

All three routes agree to four decimal places. The prediction is about 3.12 minutes above the actual 79.28-minute outcome. That error belongs to this row; the 6.04-minute MAE summarizes all 200 test rows.

The left panel is generated from the real JSON dump, not a hand-redrawn tree. The right panel shows the same arithmetic as the code. A large first correction does not mean distance or traffic alone “caused” the delivery time. It means the fitted tree assigned this row to a region whose learned correction was large.

What this audit can and cannot tell you

A path trace answers a narrow but useful question: which split conditions did this row meet, which leaf did each tree return, and how did those outputs combine? It can catch a wrong feature order, a surprising missing branch, a changed model file, or an incorrect assumption about score transformation.

It does not measure global feature importance. One path concerns one row, and a split near the root is not automatically the most important feature for every prediction. It also does not establish causation. Changing traffic_index in the input may send a row down another branch, but observational training data does not prove that real-world traffic intervention would create the same change.

For a fuller row-level attribution, XGBoost can return SHAP contributions with pred_contribs=True. Those contributions distribute the raw margin across features and a bias term. They answer a different question from reached-leaf tracing, so keep the two explanations separate.

Troubleshoot a dump or trace that looks wrong

You see f0, f1, and other generic names. Fit with a pandas DataFrame whose columns have stable names, or supply a documented feature map. More importantly, store and validate the exact training feature order before prediction.

You multiply leaf values by learning_rate again. The dumped leaf outputs in this fitted booster already produce the verified prediction. Adding another factor makes the reconstructed total too small.

You treat every Gain cell as a leaf correction. On a split row, Gain describes split improvement. On a row whose Feature is Leaf, it holds the leaf output. Filter for Feature == "Leaf" before summing corrections.

Your leaf lookup finds several rows. Node numbers repeat across trees. Match both the tree index and node ID.

The margin and displayed probability differ. A classification objective can transform the raw margin. Compare leaf sums with output_margin=True, then apply or verify the objective’s documented transformation separately.

A missing value follows an unexpected side. Read the node’s missing child. XGBoost learns a default direction for missing values in tree boosters; it does not always send them left. The XGBoost missing-value tutorial explains that behavior in depth.

The tree is too large to read. Do not interpret a dense 500-tree model by printing every line. Start with one tree or one row, filter trees_to_dataframe(), and save machine-readable audit results. Use aggregate evaluation and attribution tools for broader questions.

Recap as three checks to carry forward

First, keep names attached to features so split rules remain readable and prediction columns remain auditable. Second, pair the human-readable dump with programmatic leaf IDs; this prevents a visual guess from becoming the explanation. Third, verify the arithmetic against output_margin=True before interpreting it.

For STOP-0277, tree 0 followed nodes 0, 2, and 6. Across all trees, the model added 41.4935, 9.1639, 6.2525, 5.7889, and -0.2965 minutes to a 20-minute base. The resulting 82.4023 minutes matched XGBoost’s own margin to four decimal places.

Apply the same three checks to a low prediction, a high prediction, and a row with a missing value. Comparing those paths is more informative than staring at one large tree image: it connects readable rules to the exact numbers the model returns.
