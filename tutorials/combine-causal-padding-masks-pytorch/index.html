How to Combine Causal and Padding Masks in PyTorch Attention

Use a small batch of variable-length messages to build one Boolean mask for PyTorch scaled dot-product attention. Inspect its shape and reference weights, separate key masking from query cleanup, and verify causality and padding isolation with mutation tests.

Mehdi Lotfinejad
August 13, 2026 · 11 min read

A next-token model receives these messages in one batch:

The batch needs a common width, but it also creates two invalid attention paths. A token could read a later token, or it could assign weight to a [pad] placeholder that is not part of the message.

To combine causal and padding masks in PyTorch attention, create a lower-triangular causal mask and a per-message Boolean mask for real key positions, then join them with &. Reshape the result to (batch, 1, query, key) for torch.nn.functional.scaled_dot_product_attention, where True means the link is allowed. After attention, set padded query rows to zero because masking keys does not remove query outputs.

This tutorial builds that exact path and checks its behavior. We will not train a Transformer. Small vectors make every shape, weight, and failed test easy to inspect.

How the Combined Attention Mask Works

An attention grid has one query row for each destination position and one key column for each source position it might read. A Boolean attention mask therefore answers one question for every query-key pair: is this link allowed?

Our two rules operate on different parts of that grid:

  • The causal rule depends on row and column. Query position 2 may read key positions 0, 1, and 2, but not positions 3 or 4.
  • The padding rule depends on the batch item and key column. A three-token message may never read columns 3 and 4 because they contain padding.

The word causal means an output can depend only on information available at that point. In next-token modeling, that is the current token and the prefix on its left. Padding is different: it is a placeholder used only to make several lengths fit one rectangular tensor.

Joining the rules produces one allowed-link grid per message. The attention-head dimension has size one so PyTorch can broadcast the same mask across every head. Broadcasting means PyTorch reuses a size-one dimension without requiring us to copy the mask for each head.

This article uses the low-level scaled_dot_product_attention function, often shortened to SDPA. Its Boolean rule is important: True means a query-key pair takes part in attention. PyTorch’s nn.MultiheadAttention uses the opposite meaning for a Boolean key_padding_mask, where True means ignore that key. If you want the higher-level padding-only path, see how to mask padding in multi-head attention.

PyTorch attention expects the tensors in one batch to share a sequence width. Group the rows, convert each message to a tensor, and record its real length before adding padding:

The pad_sequence documentation defines the result as (batch, time, features) when batch_first=True. Here, that means three messages, five positions, and four features. Zeros occupy the two unused positions in message_a and the one unused position in message_b.

Zero values do not make padding harmless. A learned projection can add a bias, and positional information can make padded vectors nonzero. The mask must identify padding from lengths or token IDs, not by testing whether every feature equals zero.

In a trained layer, learned projections usually produce three different tensors. Here, we reuse the teaching vectors for all three roles so that the mask remains the only changing mechanism. Verify Behavior by Changing Blocked Inputs

A correct-looking mask shape is not enough. Test the information-flow behavior by changing values the mask should block.

The first test replaces the final real token vector in the five-token message with four large values. It compares only earlier output rows. The second test replaces every padding vector, then compares only valid output rows. Each test runs once without a mask and once with the combined mask.

Common Mistakes and Troubleshooting

Using the wrong Boolean meaning. In F.scaled_dot_product_attention, True means allowed. In nn.MultiheadAttention padding masks, True means ignored. Name low-level masks allowed or can_attend so their meaning stays visible.

Passing attn_mask with is_causal=True. The low-level function rejects that combination. Use is_causal=True when causality is the only rule. When batch-specific padding must be joined to it, put both rules in one explicit attn_mask and leave is_causal=False.

Forgetting the head dimension. A mask shaped (batch, query, key) does not align with attention shaped (batch, heads, query, key). Insert a size-one head dimension to get (batch, 1, query, key).

Masking padded queries by making a fully false row. Softmax has no valid probability distribution when every score is blocked. Mask padded keys, run attention, then multiply the returned context by the valid-query mask.

Detecting padding from zero vectors. An ordinary token vector may contain zeros, and later layers may turn padding into nonzero values. Build validity from sequence lengths or the tokenizer’s padding ID.

Applying the mask after softmax. Setting forbidden weights to zero after normalization makes allowed weights sum to less than 1. Supply the mask to SDPA, or set forbidden scores to negative infinity before softmax in a reference calculation.

Using left padding with this right-padding formula. positions < lengths marks a prefix as valid. For left padding, valid positions are at the end, and positional indexes also need careful handling. Use one padding side consistently and test the exact layout.

Leaving dropout active during a comparison test. SDPA applies dropout whenever dropout_p is greater than zero. Set it to 0.0 for deterministic tests and pass a training-dependent value in a model, as described in the official function documentation.

Checking only weight row sums. A mask can normalize correctly while pointing in the wrong direction. Change a future token and a padded token, then assert that the outputs you keep do not move.

Recap: Keep the Two Boundaries Separate

Causal masking and padding masking protect different boundaries. The causal triangle blocks keys to the right of each query. The length-based mask blocks keys that do not belong to a particular message. Boolean & combines both rules into a batch-specific allowed-link grid.

For PyTorch scaled dot-product attention, remember this working sequence:

  1. Pad variable-length vectors to (batch, time, features) and keep their real lengths.
  2. Build valid_tokens with shape (batch, time).
  3. Join valid key columns to a (time, time) causal triangle.
  4. Reshape the mask to (batch, 1, query, key), where True means allowed.
  5. Run SDPA with the explicit mask and dropout_p=0.0 when testing.
  6. Zero padded query outputs separately.
  7. Mutate a future token and padding values to verify both isolation rules.

The durable idea is not one particular tensor expression. It is the separation of jobs: keys control what each query may read, while the query-validity mask controls which returned rows the rest of the model may keep.
