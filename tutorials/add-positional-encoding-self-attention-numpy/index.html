How to Add Positional Encoding to Self-Attention in NumPy

A beginner-friendly NumPy experiment showing why self-attention alone has no position signal, how fixed sine and cosine vectors add one, and how to verify the change with two reordered instructions.

Mehdi Lotfinejad
August 9, 2026 · 11 min read

These two packing instructions contain exactly the same five tokens:

The first instruction says to scan before sealing. The second reverses those actions. A model that knows which words are present but not where they appear cannot reliably tell the instructions apart.

To add positional encoding to self-attention, create one position vector for each token row and add it to the token vector before calculating queries, keys, and values. A fixed sinusoidal encoding uses sine in zero-based dimensions 0, 2, 4, and so on, and cosine in dimensions 1, 3, 5, and so on. A reorder test can then confirm that moving tokens changes the attention result rather than merely rearranging its rows.

This tutorial builds that test with NumPy. It does not train a Transformer. Small hand-designed vectors let us isolate one question: what changes when position becomes part of the input?

Setup: Build a Small, Reproducible Order Test

You need Python 3.11 or newer and basic familiarity with Python lists. A token is one unit in a sequence, such as one word in this lesson. A vector is a row of numbers used to represent that token. You do not need calculus or previous Transformer experience.

Create a virtual environment and install the packages used by the executed lesson:

On Windows PowerShell, activate the environment with .venv\Scripts\Activate.ps1. The published artifacts were executed with Python 3.13.2, NumPy 2.5.1, pandas 3.0.3, and Matplotlib 3.11.0.

Download instruction_token_vectors.csv and save it beside your Python file. This is an original synthetic dataset released under CC0-1.0. Synthetic means it was created for the lesson rather than collected from people or a real packing system. The instructions, feature names, and values are fictional, and the rows are not embeddings from a trained model.

The lesson also saves an SVG chart. Select Matplotlib’s headless Agg backend before importing pyplot so the code works on a server without a graphical desktop:

Load the token vectors and print them before doing any matrix calculation. The six named features keep this teaching data inspectable:

Each token has six features, so its vector width is six. The names make the numbers easier to follow, but a real language model learns dense features that usually do not have a simple label per column.

How Self-Attention Works Without Position

Self-attention lets every token collect information from tokens in the same sequence. A query represents what one row is looking for, a key represents what another row can match, and a value carries the information collected from that row.

In a trained layer, learned matrices create separate queries, keys, and values. To keep this test focused, we use each input vector for all three roles. The calculation still follows scaled dot-product attention:

Softmax converts each score row into non-negative weights that sum to 1. Subtracting the largest score before exponentiation avoids overflow. Define the calculation in two small functions:

NumPy’s matmul documentation gives the two-dimensional shape rule behind the @ operator: (n, k) @ (k, m) returns (n, m). Here, (5, 6) @ (6, 5) creates a 5 × 5 score matrix, one comparison for every query-key pair. For a more detailed walkthrough of that calculation, read scaled dot-product attention in NumPy.

Run attention separately on the two instructions:

The rows in instruction B are in a different order, so comparing row zero with row zero would compare scan with seal. Restore B to A’s token order before measuring a difference:

After alignment, every weight and context value agrees within floating-point precision. The calculation did not create a new relationship when the words moved; it only moved the corresponding output rows and columns.

This property is called permutation equivariance. A permutation is a reordering. Equivariance means that reordering the input causes the output to follow the same reordering. Self-attention preserves the rows, but it has no numeric clue that position 0 comes before position 3.

The limitation becomes stronger if a later step takes the mean across token rows. A mean ignores row order, so the two plain context summaries are identical:

L2 distance is the straight-line distance between two vectors. A value of zero means the two mean context vectors are the same.

Build One Sine-and-Cosine Signal per Position

A positional encoding has the same shape as the token matrix: one row per sequence position and one column per vector dimension. Adding the matrices keeps the familiar (tokens, width) shape while making the numeric input at each position different.

The original Transformer paper defines a fixed encoding with sine and cosine waves at several frequencies. For position pos and zero-based pair index i, the two columns are:

Each sine column has a cosine partner that uses the same frequency. Faster waves change more between nearby positions, while slower waves provide patterns across longer distances. Together, the columns give each position a repeatable numeric signature without adding learned parameters.

The next function implements the formula. It accepts an even width because this version fills complete sine-and-cosine pairs:

positions has shape (5, 1), while angle_rates has shape (3,). NumPy broadcasting expands these compatible shapes to calculate a (5, 3) angle table without a Python loop. The current NumPy references confirm that sin and cos operate element by element and take angles in radians.

Read down a column to see how one wave changes across positions. Dimensions 0 and 1 change quickly. Dimensions 4 and 5 barely change across this short sequence because their wavelengths are much longer. The values are not word features; their only job is to identify position through a multi-frequency pattern.

Prove That the Reordered Instruction Now Changes the Result

Run the same attention function on the combined vectors. Keeping the attention code unchanged is important: the only new mechanism should be the position signal.

Measure the same three quantities as before. The first finds the largest aligned attention-weight change. The second does the same for context features. The third compares the mean context vectors:

All three values are now above zero. After alignment by token, at least one attention weight differs by about 0.341, and at least one context feature differs by about 1.356. Even the order-insensitive mean is no longer identical because position changed how the token rows interacted before the mean was calculated.

The executed chart combines that evidence with the five position vectors:

Start with the top-left panel: every cell is zero after the second instruction is aligned by token. The top-right panel uses the same scale but now contains nonzero differences. The lower panels show the position matrix that caused the change and summarize two context distances.

The result does not mean these hand-designed weights understand packing instructions. It proves a narrower and useful property: position is available to the calculation, so moving the same content can change its interactions.

Turn the measurements into automated checks so a later code change cannot silently remove that property:

The threshold 0.1 applies only to this controlled dataset. In another model, use a tolerance and test case that fit its numeric scale. The durable checks are “plain results align” and “position-aware results respond to the reorder.” You can download the executed positional_encoding_order_test.csv to inspect the full-precision summary.

Common Mistakes and Design Choices

Adding position after attention. Position must affect the queries and keys if it should change which tokens match. In this lesson, add it to the input before the attention calculation. Adding it only to the final context cannot change the attention weights already computed.

Attaching a position vector to a word forever. Position belongs to a row in the current sequence, not to token identity. scan receives position 0 in the first instruction and position 3 in the second.

Comparing unaligned matrices. When testing permutation equivariance, restore both query rows and key columns. Reordering only the rows of a square attention matrix produces a misleading difference.

Aligning repeated tokens by name. The lookup in this lesson works because every token is unique. If a sequence contains the same token more than once, save the actual permutation indexes and use them for alignment; list.index() always returns only the first match.

Using an odd width with this compact function. The assignment expects full sine-and-cosine pairs. Use an even embedding width, or extend the function carefully so the final unmatched dimension is handled explicitly.

Calling zero plain difference a software bug. It is the expected result after alignment. Without a position signal or mask that depends on position, the attention calculation is permutation equivariant.

Assuming sinusoidal encoding is the only choice. Some models learn absolute position embeddings. Others represent relative offsets or rotate queries and keys. These methods encode order differently. The fixed additive method here is valuable because it is deterministic, requires no training, and exposes the basic need for a position signal.

Expecting every position pair to be equally different. Sine and cosine values repeat, and finite dimensions provide a particular set of frequencies. The encoding is designed as a structured signal, not a categorical one-hot ID for each position.

Using the chart as evidence about a trained model. The measured distances describe these six-feature teaching vectors and identity projections. A trained model learns projections, uses several heads, and may combine position with padding or causal masks. Test its real tensors rather than transferring these exact numbers.

Recap: Carry the Order Signal Into Larger Attention Code

The central rule is short: token vectors describe what is present, while position vectors describe where it appears. Add both before attention so queries, keys, and values can use the combined information.

The permutation test makes that rule observable. With the same five tokens reordered, plain self-attention produced the same aligned weights and context values. Fixed sinusoidal encoding gave each row a different signal, and the aligned results changed.

When you move to batched or multi-head attention, preserve the same shape logic. Build position rows for the sequence length, broadcast them across the batch, add them to embeddings of the same width, and test a deliberate reorder. The matrices grow, but the diagnostic question stays simple: does changing position change more than the row order?
