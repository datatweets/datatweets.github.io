How ChatGPT Works: Tokenization, Attention, and Sampling

A plain-English walkthrough of what actually happens between your message and ChatGPT's reply: text becomes tokens, a transformer turns those tokens into a probability distribution over what comes next, and a sampling strategy decides which token wins — one token at a time, on repeat. Includes real tokenizer output, a toy attention example, and a look at how pretraining, fine-tuning, and RLHF shape the model doing the predicting.

Mehdi Lotfinejad
August 10, 2026 · 13 min read

People tend to describe ChatGPT in one of two ways: either it “understands” you, or it’s “just predicting the next word.” Both descriptions are doing real work, and both miss something. The mechanism really is next-word prediction — there’s no hidden module that reads your question, thinks about it, and writes an answer in some separate step. But dismissing that mechanism as “just” autocomplete undersells what happens when you stack the prediction step billions of times over and shape it with three rounds of training. If you’ve ever wanted a client to talk to a model like this over an API rather than a mental model of what’s happening inside it, our post on building an AI chatbot in Python covers that half of the picture. This one covers the other half: what’s actually happening between your prompt and the reply.

Here’s the compressed version. ChatGPT turns your message into a sequence of numeric tokens, feeds them through a transformer neural network that produces a probability distribution over every possible next token, and picks one token from that distribution according to a sampling rule. Then it appends that token to the sequence and repeats the whole process to pick the next one, and the one after that, until it decides to stop. Every word you read from ChatGPT was chosen this way, one token at a time, with the model never seeing more than one step ahead.

The One Loop Everything Else Builds On

Strip away the training details and the whole system is a single loop, repeated once per output token:

  1. Take the sequence so far (your prompt, plus whatever the model has generated already).
  2. Turn it into token IDs, then into vectors (embeddings).
  3. Run those vectors through the transformer’s stack of layers, where each token’s vector gets updated based on which other tokens in the sequence it should “pay attention to.”
  4. Take the final vector for the last position and turn it into a score (a logit) for every token in the vocabulary — tens of thousands of them.
  5. Turn those scores into probabilities and pick one, using a sampling rule.
  6. Append the picked token to the sequence and go back to step 1.

Everything below is one of these six steps, zoomed in with real code. None of it changes once training is done — a trained ChatGPT model is a fixed set of numbers (weights) that this loop reads from at every step. What makes ChatGPT specifically ChatGPT, rather than some other transformer, is which weights those are, and how they got that way — which is the training story I’ll come back to at the end.

Step 1: Text Becomes Tokens

The model never sees your actual characters. Everything starts by chopping your text into tokens — chunks that are usually shorter than a word and sometimes longer, chosen by a fixed vocabulary the model was trained with. tiktoken, the open-source tokenizer library OpenAI publishes and current ChatGPT models use, makes this easy to inspect directly:

That 54-character sentence became 12 tokens. Notice that “ChatGPT” itself split into Chat and GPT — the vocabulary was built by statistics over training text, not by anyone hand-curating which words deserve their own token — and that most tokens carry a leading space, because word boundaries matter to the tokenizer. distinguish and " distinguish" aren’t the same token at all:

Three tokens without the leading space, one token with it. This is the tokenizer’s job, and it happens identically whether the sequence is your prompt or the model’s own output being fed back in for the next step.

(These examples use tiktoken 0.13.0 against the o200k_base encoding, the tokenizer family behind current GPT-4o-class models — the exact vocabulary any given ChatGPT model uses is not published, but this is the same public tooling and encoding OpenAI ships for that model family, so the token counts and splitting behavior above are representative, not approximate.)

Step 2: Tokens Become Vectors

A token ID is just an index — the model can’t do arithmetic on “token 14065” meaningfully. So the very first thing that happens inside the network is a lookup: every token ID is swapped for a vector of numbers, called an embedding, pulled from a big table the model learned during training. Here’s the same idea at toy scale, five words and four numbers each:

At this point, “the cat sat” is a 3×4 grid of numbers, and every row was looked up completely independently of the others — “cat” gets the same vector whether it’s next to “sat” or next to a stack of pancakes. Real models use thousands of dimensions instead of 4, and add a second signal (positional information) so the network can tell word order apart, not just word identity. The step that actually lets one token’s meaning shift based on its neighbors comes next.

Step 3: Tokens Read Each Other with Attention

This is the part of the loop that turns a bag of independent word-vectors into something that behaves like a sentence. Self-attention lets every token look at every other token in the sequence and pull in a weighted mix of their information — so “bank” ends up meaning something different next to “river” than it does next to “loan,” even though it started as the exact same embedding vector in both cases.

Mechanically, each token produces three vectors — a query, a key, and a value — and the attention weight between any two tokens is how well one token’s query matches another’s key:

Row 1 of weights says: to build token 1’s new representation, take 16.8% of token 1’s own value, 56.4% of token 2’s, and 26.7% of token 3’s — every row is a full probability distribution over the sequence. That’s the “attention” — a learned, per-token weighting of everyone else in the sequence, computed fresh for every input. Real models run dozens of these in parallel (“multi-head” attention) and stack dozens of layers of it, each layer refining the representation further. I’ve kept this toy version deliberately small; if you want the full derivation — masking, multiple heads, positional encoding, and a complete transformer block trained end to end — the self-attention module in our free Transformers from Scratch course builds exactly that, and our scaled dot-product attention post derives the formula above line by line.

Step 4 and 5: From Logits to a Chosen Token

After the last transformer layer, the vector at the final position gets multiplied against the embedding table one more time (in reverse), producing one raw score — a logit — per token in the vocabulary. A softmax turns those logits into a probability distribution, and then a sampling rule decides which single token actually gets picked. This is the step where “temperature” lives, and it’s worth seeing on numbers you can check by hand. Imagine the model has just generated “The best vacation spot is the…” and the next-token logits, restricted to five plausible words, look like this:

Lower temperature sharpens the distribution toward the top choice — at 0.5, “ocean” and “beach” eat up 99% of the probability between them, and “tundra” is functionally impossible. Higher temperature flattens it out, giving the less-likely words a real (if still small) shot. Two strategies then use this distribution differently:

Greedy decoding always takes the top-scoring token — deterministic, but it makes ChatGPT sound stiff and prone to looping on repeated phrases. Sampling draws from the distribution, so the same prompt can produce different phrasing on different runs, which is closer to how the product actually behaves. Production systems layer more controls on top of raw sampling — top-k and top-p (nucleus) sampling both trim away the unlikely tail before drawing — and our Generation & Sampling module works through all of them against a model you train yourself.

Turning a Chat Into One Long Sequence

ChatGPT looks like a conversation, but the model underneath only ever does the loop above on one flat sequence of tokens. The system prompt, your messages, and the model’s own previous replies all get concatenated into one string with role markers before anything gets tokenized:

The role markers here (<|system|>, <|user|>, <|assistant|>) are a stand-in for illustration — real chat templates use specific reserved tokens the model was trained to recognize — but the shape is exactly right: everything becomes one string, and the model generates by continuing it after <|assistant|>, one token at a time, using the same loop from step 1 through step 5. That’s also why nothing your program doesn’t resend gets “remembered” between API calls; the AI chatbot post covers that consequence in more depth.

Three Places This Trips People Up

Numbers tokenize inconsistently, which is a real source of arithmetic mistakes. Digits don’t get one token each — they get grouped by whatever chunks showed up often in training text, and the grouping isn’t stable across similar-looking numbers:

382 is one token on its own, but the instant you add a fourth digit it splits into 382 + 9 — not 3829 as a whole, and not an even 38 + 29 split either. The model isn’t doing arithmetic on digits the way you are; it’s predicting plausible token continuations, and inconsistent chunking is exactly why long multiplication and multi-digit addition are places ChatGPT is more likely to slip.

The same idea costs more tokens in some languages than others. Compare an English sentence with a Persian one of similar meaning:

The Persian sentence is shorter in characters but needs more tokens, because the vocabulary was built mostly from English-heavy training text and represents English in bigger chunks. That has a real cost: a fixed context window (see below) and per-token API pricing both hit non-English text harder for the same amount of meaning.

Every token costs the same amount of “thinking.” The loop above runs the exact same number of transformer layers whether it’s predicting the next token of “2 + 2 =” or the next token of a hard proof — there’s no separate mode that spends more compute on harder problems, inside this base loop. This is a real limitation, and it’s also why prompting tricks like “think step by step” work at all: they don’t make any single prediction smarter, they make the model produce more tokens on the way to an answer, spreading a fixed per-token compute budget across more steps. Our prompt engineering module covers techniques that lean on exactly this mechanism.

Where the Weights Come From: Training in Three Stages

Everything above describes the fixed loop a trained model runs. The interesting question is where the weights inside that loop come from — and ChatGPT-style models get there in three distinct stages, not one:

  1. Pretraining. The model is trained on a huge amount of text with one task: given the tokens so far, predict the next one, over and over, on trillions of tokens. Nobody is grading whether the answer is helpful — only whether it matches what actually came next in the training text. This stage is expensive (it’s where the bulk of the compute goes) and produces a model that’s good at continuing text plausibly, not at following instructions. Our bigram language model post builds this exact task — next-token prediction from counted probabilities — at a scale small enough to fully inspect.
  2. Supervised fine-tuning (SFT). The pretrained model is then trained further on a much smaller set of curated examples that look like the chat format from the section above: a prompt, and a high-quality human-written (or human-edited) reply. This is what teaches the model to behave like an assistant answering a question, rather than a generic text-continuer.
  3. Preference tuning (RLHF and similar methods). Humans rank multiple candidate replies to the same prompt from best to worst. That ranking data trains the model to prefer outputs people actually rate as more helpful, honest, and safe — nudging the same next-token-prediction weights toward replies real reviewers preferred, without anyone hand-writing a rule for what “helpful” means.

None of these stages change the mechanism from the sections above — the model that comes out the other end is still just predicting one token at a time from a probability distribution. What changes across the three stages is which token that distribution tends to favor.
