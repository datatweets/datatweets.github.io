How to Diagnose Vanishing Gradients in PyTorch Networks

A beginner-friendly gradient-flow audit for a deep PyTorch classifier. Measure weight-gradient RMS after one backward pass, read the input-to-output pattern, compare Sigmoid/Xavier with ReLU/Kaiming, and verify the effect on training without relying on a magic cutoff.

Mehdi Lotfinejad
August 13, 2026 · 11 min read

A neural network can finish every epoch without an error while its early layers barely learn. In the executed example below, the first hidden layer had a weight-gradient RMS of only 2.691e-07; the output layer had 2.244e-01. The training loop was running, but the correction signal became tiny before it reached the input side.

To diagnose vanishing gradients in PyTorch, run a normal forward pass and loss calculation, call backward(), then inspect parameter.grad for each layer before optimizer.step(). Compare layer gradient sizes from output to input across several batches: a repeated drop by many orders of magnitude toward the first layers, together with stalled learning, is evidence of vanishing gradients.

We will make that pattern visible in an eight-hidden-layer classifier. It uses fictional indoor-air readings to predict a ventilation alert. Then we will change the hidden activation and its matching weight initialization, rerun the same audit, and check whether the training behavior changes.

Setup and the data we will hold constant

You need Python 3.11 or later and basic knowledge of Python functions. You should know that a neural network contains adjustable values called weights, but you do not need calculus. For a slower introduction to forward passes and backpropagation, read Build a Neural Network from Scratch with NumPy.

Understanding why the correction signal shrinks

A gradient shows how a small change to a weight would change the loss. Backpropagation starts at the loss and applies the chain rule through each earlier operation. If many local derivatives have magnitudes below one, multiplying them through a deep path can leave the early layers with extremely small gradients. This is the vanishing-gradient problem.

The gradient does not need to be large everywhere. Different layers have different shapes and roles, so comparing one raw element is not useful. We will summarize each weight matrix with gradient root mean square, or gradient RMS:

RMS keeps the unit of the individual values and depends less on matrix size than a total norm does. We care most about the pattern across layers and repeated batches, not one universal threshold.

PyTorch’s current autograd documentation explains that backward() computes gradients for tensors that require them. The Tensor.grad reference adds an important detail: .grad starts as None, is populated by backward(), and accumulates on later backward calls unless you clear it.

Build a network that makes the symptom visible

Both networks will use eight hidden layers with 32 units per layer. The first uses sigmoid hidden activations. A sigmoid maps every input to a value between zero and one. Sigmoid derivatives can be small, so multiplying them across this deliberately deep stack makes weak backward flow easy to see.

The comparison network uses ReLU, which keeps positive values and replaces negative values with zero. Each activation gets a matching initialization: Xavier for sigmoid and Kaiming for ReLU. PyTorch’s torch.nn.init reference documents the recommended gain values and the Kaiming initializer’s nonlinearity setting.

This is a diagnostic architecture, not a default recommendation for tabular classification. Its depth makes the change in signal size easy to see on a CPU.

Measure gradients before the optimizer changes anything

Use the same 128 training rows for both audits. For each model, clear old gradients, calculate cross-entropy loss, and call backward(). Do not call optimizer.step() yet; we want to inspect the correction signal produced by one unchanged batch.

Create both models with the same seed, run one backward pass for each, and print the measurements in scientific notation. Scientific notation makes very small values readable: 2.691e-07 means 0.0000002691.

Read the sigmoid column from bottom to top, following backpropagation toward the inputs. Its output-layer RMS is 2.244e-01, but hidden_1 receives only 2.691e-07. The input-side value is about 1.2e-06 of the output-side value. That smooth, repeated decline across the stack is more informative than declaring one number “too small.”

The ReLU/Kaiming model shows a different shape. Its hidden-layer values remain between about 4.99e-03 and 8.39e-03, and its first hidden-layer gradient is about 30,018 times the sigmoid model’s first-layer value. This comparison changes two linked choices together, so it shows that the activation-initialization pairing improves gradient flow in this example. It does not prove that ReLU alone explains the complete difference.

The full executed measurements are available in gradient_audit.csv.

Troubleshooting misleading gradient audits

Reading gradients after clearing them. Calling optimizer.zero_grad() or model.zero_grad() after backward() removes the values you meant to inspect. Audit after loss.backward() and before clearing or stepping.

Forgetting that gradients accumulate. A second backward pass adds to existing .grad values by default. Clear gradients before every independent audit. Otherwise, an old batch can make the current signal look larger.

Looking only at the total L2 norm. A large matrix often has a larger total norm simply because it has more elements. RMS makes matrices of different sizes easier to compare. You should still record layer shapes and inspect more than one summary when debugging a serious model.

Using a magic threshold. 1e-6 is not universally bad, and 1e-2 is not universally good. Parameter scale, loss reduction, batch size, precision, and architecture all affect the numbers. Look for a persistent layer-wise collapse, compare with update sizes, and connect it to stalled learning.

Auditing one unusual batch. Repeat the measurement over several representative batches. Report a median or range per layer. A batch with only one class or extreme values may create an unrepresentative pattern.

Changing many settings without preserving a baseline. Activation, initialization, normalization, residual connections, depth, and optimizer choice can all affect gradient flow. Change one coherent hypothesis at a time and rerun the same stored batch. Here, activation and its matching initialization form one deliberate pair.

Confusing None with a zero gradient. None may mean the parameter did not participate in the graph, has requires_grad=False, or was checked before backward(). A tensor filled with zeros is a computed gradient with a different meaning.

Fixing flow while ignoring generalization. The ReLU model learns, but its validation loss rises late in this run. Solving vanishing gradients does not solve overfitting, data leakage, poor labels, or an unsuitable metric.

Expecting identical numbers on every device. Seeds and deterministic settings help reproduction, but floating-point results can vary across PyTorch versions, hardware, and CPU or GPU kernels. Preserve the environment and focus on the large pattern rather than the final decimal place.

What you learned: a debugging habit worth keeping

The durable lesson is to inspect the signal that training uses, not only whether the loop is running. A healthy-looking progress bar cannot tell you whether an early layer receives a meaningful correction.

This audit used four checks: standardize the inputs with training-only statistics, run one unchanged batch through backward(), summarize each weight matrix with gradient RMS, and read the layer pattern beside the loss curve. The deep sigmoid network showed a smooth drop from 2.244e-01 at the output to 2.691e-07 at the input side and then stalled near the majority-class result. The ReLU/Kaiming version preserved a stronger hidden-layer signal and learned the synthetic task more effectively.

For your own model, save one representative batch and a small audit table before changing anything. Repeat the table after one targeted change. When the gradient pattern and learning curve improve together, you have stronger evidence that you fixed the cause rather than merely changed the symptom.
