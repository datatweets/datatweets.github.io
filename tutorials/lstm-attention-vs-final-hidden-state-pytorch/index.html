LSTM Attention vs Final Hidden State: 100% vs 60.6% Accuracy

A controlled PyTorch comparison of two nearly parameter-matched LSTM classifiers: one compresses a sequence into its final hidden state, while the other uses a query and additive attention to retrieve one earlier component reading.

Mehdi Lotfinejad
August 14, 2026 · 12 min read

A sequence contains readings for components A through L in random order. Its last row asks about one component, such as F. A model must find F’s earlier reading and decide whether it signals an alert. The answer may appear 12 time steps before the query.

To test whether attention helps an LSTM retrieve an earlier item, train two nearly parameter-matched classifiers. One predicts from the LSTM’s final hidden state; the other scores every earlier key, applies softmax, and combines the resulting context with the final state. Across five controlled runs on the same 600 test sequences, final-state accuracy averaged 60.6%, while keyed attention reached 100.0%. This result applies to the designed retrieval task, not every sequence problem.

Understanding the retrieval bottleneck

An LSTM, or long short-term memory network, reads an ordered sequence while carrying numeric memory from one step to the next. PyTorch returns two useful outputs: a hidden state for every step and a final hidden state named h_n. With batch_first=True, the step-by-step output has shape (batch, sequence, hidden).

A common classifier uses only h_n. That creates this path:

The final state has to keep enough information about every reading that might matter later. It does not know which component the last row will request until it reaches that row. In our task, a 12-number state must retain information about 12 readings and their component identities, then answer one query.

Attention adds a retrieval path. A query describes what the model needs, a key identifies each available item, and a value holds the information that can be retrieved. Here, the final row supplies a component query. The earlier component identities are keys, and their LSTM states are values.

The attention model calculates one score per earlier row:

PyTorch’s current Softmax documentation states that softmax produces values from 0 to 1 that sum to 1 along the chosen dimension. The context is therefore a weighted mixture of the earlier states. The classifier receives both the context and the final hidden state.

This lesson uses keyed additive attention. “Additive” means that transformed keys and queries are added before a small scoring layer. It is an intentionally narrow retrieval model, not a full language translator or Transformer.

Previous LSTM knowledge is helpful but not required; if three-dimensional sequence shapes are unfamiliar, start with shaping time-series data for an LSTM.

Each sequence has 12 reading rows followed by one query row. A positive reading for the queried component gives alert_label=1; a negative reading gives 0. The label is repeated within a sequence for easier auditing, but it is never an input feature.

Build a nearly parameter-matched final-state model

The baseline passes the entire sequence through one 12-unit LSTM and discards the per-step output. It sends only final_hidden[-1] to a small classifier. The two-layer head makes the baseline’s total parameter count nearly equal to the attention model’s count, so extra parameters alone do not explain a large gap.

The official nn.LSTM reference documents this return structure. With one forward layer, final_hidden[-1] has shape (batch, hidden_size), which is (batch, 12) here.

The model returns logits, unrestricted scores before conversion to probabilities. During training, BCEWithLogitsLoss combines the sigmoid conversion and binary cross-entropy calculation in one numerically stable operation.

Add the keyed attention path

The attention version keeps the same LSTM size. It reads component one-hot vectors as keys and the last row’s component as the query. The attention weights mix the first 12 LSTM states into one context vector.

Read the forward method in four steps: run the LSTM, score the key-query pairs, normalize the scores, and combine the states.

The score tensor has shape (batch, 12): one number for each component reading row. Softmax runs across dim=1, so each sequence gets its own 12 weights totaling 1. torch.bmm then multiplies (batch, 1, 12) weights by (batch, 12, 12) states and returns one 12-number context per sequence.

Returning weights is not needed for classification, but it lets us verify retrieval. A useful test asks whether the highest-weight position contains the same component as the query.

Both models use the same 12-unit LSTM. Their total sizes differ by only two trainable numbers.

Train five matched runs and open the test set

One random initialization can favor one model. We therefore train each model five times with controlled seeds. Every paired run sees the same training rows in the same batch order, uses Adam with a learning rate of 0.005, and runs for 30 epochs. The validation split confirms that the fixed recipe trains as expected; it is not used to select the best run.

After training, classify a row as alert when its logit is at least zero. That equals a sigmoid probability of at least 0.5. The executed results were:

The final-state model stays between 59.0% and 62.0% on the locked test sequences. The attention model classifies all 600 test sequences correctly in every run. It also places its largest weight on the queried component in every test sequence.

This is evidence for a specific mechanism on a controlled task. The final-state model must compress all readings before it knows which one will be requested. The attention model can use the final query to retrieve an earlier state. The test does not show that an LSTM can never retain long-range information, or that attention will always improve real data.

An attention weight has a limited meaning. It shows how this attention layer mixed the stored states. It does not prove a causal explanation for every operation inside the LSTM. Here we can check it against the known synthetic query, which makes top-key match a valid mechanism test.

Common mistakes and troubleshooting

Using the label as an input. alert_label exists only for training and evaluation. Do not place it in the 14 input features. That would leak the answer into the model.

Splitting individual CSV rows. Rows from one sequence must stay together. Split unique sequence_id values first, or use the supplied split column.

Scoring the query row as a stored item. The query is at index 12. Attention should score inputs[:, :12], not all 13 rows, because the last row asks the question rather than supplying a reading.

Applying softmax across the batch. Use dim=1 for scores shaped (batch, sequence). Using dim=0 makes unrelated sequences compete for weight.

Mixing keys and states after reordering. Each key must stay aligned with the LSTM state from the same step. If preprocessing reorders one array without the other, a correct match retrieves the wrong value.

Comparing models with different data orders. A controlled comparison should keep splits, batch orders, epochs, optimizer settings, and the evaluation rule fixed. Reset the seed before constructing each model, and record the package versions.

Reading perfect synthetic accuracy as operational proof. The dataset has one clean query, one reading per component, no missing keys, and a direct sign-based label. Real sequences may have repeated keys, noisy labels, irregular lengths, or queries that need several pieces of evidence.

Assuming more parameters caused the result. The final-state model has 1,667 parameters and the attention model has 1,669. Matching counts does not make the models identical, but it removes a large capacity difference as the simple explanation.

If the attention model remains near chance, first print the query one-hot vector, the 12 record keys, and weights.sum(dim=1). Confirm that the queried component exists exactly once and that every weight row sums to approximately 1.

Recap: separate remembering from retrieving

A final hidden state asks one fixed-width vector to remember an entire sequence. That can work when the needed information is compact or naturally preserved. It becomes a harder design when a late query may request any one of several earlier details.

Attention keeps the earlier states available. A query scores their keys, softmax turns the scores into weights, and a weighted sum creates the context used for the decision. In this parameter-matched synthetic test, that retrieval path raised mean test accuracy from 60.6% to 100.0% and selected the correct component in every held-out sequence across five runs.

The durable lesson is not that attention always wins. It is that architecture should match the information path. When a task says “find the earlier item that matches this later request,” test an explicit retrieval path and verify both its predictions and its weights.
