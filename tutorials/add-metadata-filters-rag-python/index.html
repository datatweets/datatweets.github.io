How to Add Metadata Filters to RAG Retrieval with Python

Build a transparent metadata filter for RAG retrieval, apply region, plan, and status rules before ranking, and measure why filtering only the global top results can remove every useful candidate.

Mehdi Lotfinejad
August 3, 2026 · 11 min read

A support search asks how long a deleted report can be recovered. The text matcher returns a clear answer, but it comes from an archived policy for another plan. Similar wording has hidden the document that the user is allowed to receive.

To add metadata filters to RAG retrieval, store fields such as status, region, and minimum plan beside every document. For each query, build an eligibility mask from those fields, then rank only the eligible document vectors. Do not retrieve a global top-k list and remove ineligible rows afterward: the correct eligible document may already fall below that cutoff.

This tutorial tests that rule with a small Python retriever. RAG, or retrieval-augmented generation, finds supporting text before a language model writes an answer. We will focus on retrieval and leave answer generation out, so every ranking decision remains visible.

Understanding Eligibility Before Similarity

Metadata is structured information about a document rather than its main text. Here, status, region, and min_plan are metadata. The document body may answer a question; the metadata decides whether the document can be returned for that query.

The lesson uses this eligibility rule:

A current global Free document can serve any region and plan. A current Europe Team document can serve a Europe query on the Team or Enterprise plan. An archived document is always excluded. These rules are fictional, but their shape is common: combine access, locale, product, date, or document-state conditions before ranking.

Retrieval then follows two separate stages:

An eligibility mask is one True or False value per document. True means the row can be returned for this query. Top-k means the first k ranked results; this lesson uses k=3.

Order matters. If search first selects three documents from the full collection, all three can be ineligible. Removing them afterward gives an empty list, even when a valid document ranked fourth. Filtering before ranking allows every eligible document to compete for all three positions.

This is not the same as adding words such as apac or free to the question. Text similarity is a soft score, so an exact but forbidden phrase may still win. Eligibility is a hard rule: a document either enters the candidate set or it does not.

Build One Text Index and One Eligibility Rule

TF-IDF gives more weight to words and short phrases that are useful in fewer documents. Scikit-learn’s current TfidfVectorizer reference defines ngram_range=(1, 2) as single words plus adjacent two-word phrases. It also documents sublinear_tf=True as replacing raw term frequency with 1 + log(frequency).

Cosine similarity compares the direction of two numeric vectors. A larger score means their weighted terms point in a more similar direction. The official scikit-learn pairwise metrics guide notes that cosine similarity is a common choice for TF-IDF document vectors.

Now encode the plan order and return one Boolean mask. The parentheses are important because pandas combines each condition element by element:

Series.isin() checks exact membership. The current pandas Series.isin() reference explains that it returns one Boolean value per element. A single string is not accepted, which is why the code passes the list ["global", region].

Do not treat the numeric plan rank as a similarity feature. Its meaning is an ordered permission rule, not a distance. Giving Enterprise the value 2 does not make it “twice as similar” to Team as Free.

Test the Rule Across All 12 Questions

One successful example is not enough. The complete build applies all three methods to every labeled question and records four measures:

  • Hit@1: the labeled document is first.
  • Hit@3: the labeled document appears in the returned top three.
  • Eligible result rate: the share of returned rows that satisfy all metadata rules.
  • Candidate coverage: the share of available top-k eligible slots filled with eligible rows.

For candidate coverage, the denominator is the smaller of three or the total eligible document count. This avoids asking a query with only two eligible documents to return three.

Unfiltered retrieval fills three positions, but only 11.1% of its returned rows are eligible. Post-filtering raises that rate to 100% by removing forbidden rows. However, it finds the labeled document within its remaining results for only 33.3% of questions and fills only 11.1% of the available eligible slots.

Pre-filtering reaches 100% on all four measures. These perfect values describe a deliberately small synthetic test, not expected production performance. The important evidence is the contrast under one fixed TF-IDF index: changing filter placement changes which documents have a chance to rank.

Read the left panel as labeled retrieval accuracy. Read the right panel as scope control and result coverage. Post-filtering looks safe if you examine only the 100% eligible-result bar, but the adjacent 11.1% coverage bar reveals that it discarded most available candidates.

For a production evaluation, add real query patterns, a held-out set, empty-scope cases, and several relevant documents per question. If you also need to choose passage boundaries, the RAG chunk-size testing tutorial shows how to keep development and holdout questions separate.

What Can Go Wrong

Filtering after top-k. This is the central failure. Retrieving three global results and then applying eligibility rules can produce fewer than three results or none. Apply hard eligibility constraints during candidate selection, then choose the best k among those candidates.

Using metadata words as a substitute for a filter. Adding “Europe Team” to the query may influence similarity, but it cannot guarantee exclusion. Keep hard rules separate from soft relevance scores.

Treating global as every region. A global document is a fallback in this fictional rule. Your system may require a region-specific document to override it. Encode precedence explicitly and add labeled cases where global and regional documents are both eligible.

Letting unknown plans pass. PLAN_RANK[plan] raises KeyError for an unexpected value. That fail-closed behavior is safer than quietly mapping an unknown plan to Enterprise. Validate query metadata at the application boundary and log rejected values.

Keeping archived vectors without a status check. An archived document can be the closest text match. Either remove it from the searchable index or require status == current in every retrieval path. Test both direct search and any cached or fallback path.

Mixing authorization with personalization. Region and plan are teaching fields here. If a field controls private data access, enforce it in a trusted server-side layer. Do not accept a client-supplied tenant ID or access level without verifying the user’s identity and permissions.

Returning weak but eligible text. Q01’s second and third pre-filter results are allowed but unrelated. Add a validated relevance threshold, reranker, or abstention rule after eligibility. Measure false abstentions as well as unwanted context.

Fitting a new vectorizer for each query. Fit the TF-IDF vocabulary on the document collection and use transform() for new questions. A separately fitted query vector has a different feature space and cannot be compared correctly.

Assuming this lexical baseline understands synonyms. TF-IDF depends on shared words and phrases. You can replace it with embeddings or hybrid retrieval while keeping the same metadata mask and evaluation cases. The hybrid RAG search tutorial shows how to combine lexical and semantic ranks.

Ignoring empty eligible sets. A query may have no current document for its scope. Return a clear “no eligible evidence” state rather than relaxing the filter or sending arbitrary context to a generator.

Opening a chart window on a server. Select Matplotlib’s Agg backend before importing matplotlib.pyplot, then save the chart. The official Matplotlib backend guide lists Agg as a non-interactive backend for file output.

Where to Go Next: Freeze the Retrieval Boundary

Metadata filtering and text ranking answer different questions. The filter asks which documents are allowed and applicable. The similarity score asks which of those documents best match the text. Keep that order visible in code: build an eligibility mask, rank only the rows marked True, and then apply relevance or answer-generation checks.

In this executed lesson, late filtering returned only 11.1% of the available eligible slots, while pre-filtering filled all of them and placed every labeled document first. Those numbers come from 12 designed cases. They prove that the implementation follows this dataset’s rules, not that TF-IDF or these metadata fields will solve every RAG system.

Before deployment, turn your real scope policy into small test cases. Include valid global fallbacks, region overrides, expired documents, unknown metadata, no-result queries, and users near each permission boundary. Save the retrieved IDs for every case. A RAG answer can be grounded only in the evidence that survives that boundary.
