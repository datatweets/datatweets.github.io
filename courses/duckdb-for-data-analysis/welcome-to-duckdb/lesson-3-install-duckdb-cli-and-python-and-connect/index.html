Welcome to Installing DuckDB#

DuckDB gives you two front doors to the same engine: a standalone command-line tool for working directly in a terminal, and a Python package for using it inside a script. This lesson installs both, on whichever platform you’re on, then proves each one works with a query you run yourself.

By the end of this lesson, you will be able to:

  • Install the DuckDB CLI on macOS, Linux, or Windows
  • Install DuckDB’s Python package with pip
  • Connect from both the CLI and Python and confirm you’re talking to the version this course is built against
  • Know where the Windows-specific VC++ Redistributable requirement fits in, before it surprises you

This whole course is written and verified against DuckDB 1.5.5 — the version pinned for every module, confirmed against duckdb.org/install directly. If a later install gives you a newer version, everything in this lesson should still work; only exact output formatting might differ slightly.

This lesson’s code was run against DuckDB 1.5.5, verified on 2026-08-11 — the version and date this whole course is pinned to. If duckdb.connect() on your machine reports a newer patch version, the SQL and behavior below should still hold.

Fix the installer’s own suggested line before using it

The installer’s hint above has a real bug: export PATH="~/.duckdb/cli/latest":$PATH puts the ~ inside double quotes, and shells don’t expand ~ to your home directory inside quotes — that line silently sets PATH to a folder that doesn’t exist, and duckdb still won’t be found. Use $HOME instead, which does expand inside quotes: export PATH="$HOME/.duckdb/cli/latest":$PATH.

Add the corrected export PATH line to your shell profile (~/.zshrc on a default macOS setup) and open a new terminal, then confirm:

Windows#

Also written from duckdb.org/install’s current instructions, and also not independently captured on a Windows machine for this lesson.

Windows needs the Visual C++ Redistributable

On Windows, both the DuckDB CLI and the Python package depend on the Microsoft Visual C++ Redistributable. If it isn’t already installed (most systems that already run other Windows software have it), duckdb will fail with a DLL-loading error that gives no hint about the actual cause. Install it from Microsoft’s official download page before troubleshooting anything else — it’s a small, one-time download.

Confirm the same way: duckdb --version in a new terminal.

Connect from the Python API#

With the package installed, connecting is one function call:

duckdb.connect() with no arguments opens a private, in-memory database — nothing is written to disk, and it disappears when the connection closes. Pass a file path instead (duckdb.connect("thistlewood.duckdb")) to open or create a persistent database file; a later module in this course covers that distinction in depth.

Each connect() Call Is Its Own Private Database#

It’s worth confirming directly what “private” means here, since it’s easy to assume every in-memory connection shares one global space. It doesn’t:

duckdb.connect() and duckdb.connect(":memory:") both open an in-memory database, but each call creates its own independent one — a table created on first simply doesn’t exist as far as second is concerned. If you need two connections to share data, either pass the same open connection around, or use a file-backed database both connections open by the same path (a later module covers that setup).

Notice both queries above returned 42 for the identical arithmetic — that’s not a coincidence. Practice Exercises#

Exercise 1: Check your own version#

Install DuckDB’s CLI and Python package on your own machine following this lesson’s steps for your platform, then run duckdb --version and the Python PRAGMA version query. Confirm both report the same version number as each other.

Hint

If you installed the CLI and the Python package at different times, they can drift to different versions — that’s fine for this course, but worth knowing about; a version mismatch is a common source of confusing behavior differences between the two front doors.

Exercise 2: A persistent database file#

Using the Python API, connect with a file path instead of no arguments: duckdb.connect("practice.duckdb"). Create a tiny table, insert one row, close the connection, then reconnect to the same file path and query the table again. Confirm the row is still there — proof the file, not just the in-memory session, is what’s durable.

Summary#

DuckDB installs two ways: a standalone CLI (via Homebrew, an install script, winget, or a direct download, depending on platform) and a Python package (pip install duckdb, identical everywhere). Both were confirmed working directly — the CLI reported v1.5.5 after installation, and the Python API’s PRAGMA version reported the same. Both front doors embed the exact same engine, proven by both returning identical results for the same query.

Key Concepts#

  • DuckDB CLI — a standalone executable providing an interactive (or single-command, via -c) SQL prompt.
  • duckdb.connect() — opens a Python connection; with no argument, an in-memory database; with a file path, a persistent one.
  • VC++ Redistributable — a Windows-only prerequisite for both the CLI and Python package; install it before troubleshooting a DLL error.

Why This Matters#

Every lesson after this one assumes DuckDB is installed and connectable — from the CLI, from Python, or both. Getting this step solid and verified now means the rest of the course is about SQL and data, not fighting an install.
