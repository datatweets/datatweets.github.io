Welcome to the DuckDB UI#

Every query so far has come back as text — a terminal table or a printed DataFrame. DuckDB also ships a full browser-based interface: a notebook where you write SQL in cells, run them, and see results as an interactive, sortable, scrollable table, without leaving DuckDB or installing anything separate. This lesson starts it, points it at Thistlewood Goods data, and shows you two screenshots of it running — not a mockup of what it might look like.

By the end of this lesson, you will be able to:

  • Start the DuckDB UI from Python (or the CLI) with three commands
  • Recognize its notebook layout: cells, a run button, and a results panel with inferred column types
  • Run a query against a Thistlewood Goods file inside the UI and read its results
  • Shut the UI server down cleanly when you’re done with it

This lesson’s code was run against DuckDB 1.5.5, verified on 2026-08-11 — the version and date this whole course is pinned to. If duckdb.connect() on your machine reports a newer patch version, the SQL and behavior below should still hold.

Starting the UI#

Get the data

This lesson uses thistlewood_orders_flat.csv, and thistlewood_products.csv, hosted at https://datatweets.com/datasets/thistlewood/thistlewood_orders_flat.csv, and https://datatweets.com/datasets/thistlewood/thistlewood_products.csv. Download them into your working directory to follow along by bare filename, or skip the download and point DuckDB straight at the URLs instead — DuckDB reads HTTPS sources directly in a FROM clause, so the full https://... URL works anywhere the bare filename does, with no other setup.

The UI is a bundled DuckDB extension, not a separate install. Three statements get it running:

INSTALL ui downloads the extension once (DuckDB caches it after that), LOAD ui makes its functions available in this connection, and CALL start_ui() starts a local web server — on localhost, nothing exposed to your network — and opens it in your default browser. get_ui_url() gives you that same address if you need it (for scripting, or if a browser window didn’t open automatically). CALL stop_ui_server() shuts it down again; ui_is_started() confirms the state both before and after, which matters if you’re starting and stopping the UI repeatedly in a script rather than leaving it running in a terminal session.

The CLI shortcut

From the DuckDB CLI, duckdb -ui does the same three-step startup in one flag — useful if you’re not already in a Python session and just want the UI open against a file.

What You See on First Launch#

Opening that URL for the first time shows a default onboarding notebook, “DuckDB UI basics,” with a few pre-written example cells explaining the interface. In the top-right corner sits a “Sign in to MotherDuck” button — MotherDuck is DuckDB’s optional hosted cloud product, and this course confirmed directly that the button is exactly that: optional. Every capability this lesson uses — writing a query, running it, browsing results — worked fully with no account and no sign-in, consistent with this course’s no-cloud-account approach throughout.

The left sidebar lists your notebooks and attached databases; the main panel holds the notebook’s cells, each with its own run button and, once run, its own results section directly beneath the query.

Running a Query in the UI#

A new, empty notebook with one query cell — asking the same category-summary question Lesson 2 answered with pandas and DuckDB side by side — looks like this once run:

Notice the right-hand panel: 8 Rows, 3 Columns, with each column’s inferred type listed underneath — the same schema-inference behavior you’ve seen from the CLI and Python all module, just rendered visually instead of printed as text. The numbers match exactly: Bath leads at an average price of $273.46 across 8 products, down to Outdoor at $133.46 across 7 — the identical result Lesson 2’s pandas-versus-DuckDB comparison produced.

A second cell, a different question — the ten highest-value individual order line items — shows the same pattern: write SQL, run it, read the result grid.

Both screenshots show the same thing Lessons 1 through 4 already proved with text output: DuckDB reading a file directly, no load step, with an inferred schema you can inspect before or after running a query. The UI doesn’t change what DuckDB does — it changes how you see it.

The UI Shares Its Connection’s State#

One detail worth confirming rather than assuming: does the UI notebook see data created by the Python connection that started it, or is it a separate, disconnected session? Test it directly — create a table from Python, then query it from a UI cell with nothing else in between. This block launches a real browser window, so it’s shown here rather than run automatically — follow along on your own machine to see the result:

Running SELECT * FROM python_side_table; in a fresh notebook cell returns the single row (x = 1) without any ATTACH or reload step, and python_side_table shows up directly in the sidebar’s attached-databases tree, under memory > main. The UI isn’t a separate session with its own copy of anything — it’s a window onto the exact same in-memory database the Python connection that called start_ui() is holding open. Close that Python process and the in-memory data (and the UI session backed by it) goes away with it, the same lifetime rule Lesson 3 established for any duckdb.connect() call with no file path.

Practice Exercises#

Exercise 1: Start it yourself#

Run this lesson’s startup code on your own machine (or duckdb -ui from the CLI), and let the browser window open. Find the “Sign in to MotherDuck” button and confirm you can still run a query — any query — without clicking it.

Hint

Add a new cell, write any SELECT statement against a file you have locally (or even SELECT 1;), and click its run button. No account or sign-in step should be required anywhere in that path.

Exercise 2: A third query#

In the same notebook, add a cell that queries thistlewood_orders_flat.csv for the number of line items and total revenue per month (hint: order_date is a real DATE column, not text, so use strftime(order_date, '%Y-%m') to get a YYYY-MM string to group by, rather than slicing characters out of a string that isn’t there). Compare your result to what a plain Python/CLI query against the same file would give you — they should match exactly, since it’s the same engine either way.

A version-specific gotcha: date_trunc’s return type

If you reach for date_trunc('month', order_date) instead, know that on this course’s pinned DuckDB 1.5.5 it returns a TIMESTAMP, not a DATE — a change from the 1.4.x line. strftime sidesteps the question entirely by returning a plain string, which is what this exercise actually wants to group by.

Summary#

The DuckDB UI is three commands away — INSTALL ui, LOAD ui, CALL start_ui() — and gives you a notebook interface for the exact same engine every other lesson has used from the CLI and Python. Two screenshots in this lesson showed it running against Thistlewood Goods data: a category summary matching Lesson 2’s numbers exactly, and a top-ten order-value query matching a plain SQL ORDER BY ... LIMIT. The “Sign in to MotherDuck” button sits in the corner but was never needed for anything this lesson did. CALL stop_ui_server() shuts the server down cleanly when you’re finished, confirmed by ui_is_started() flipping back to False.

Key Concepts#

  • start_ui() / stop_ui_server() — starts and stops DuckDB’s bundled local web UI; ui_is_started() reports its current state.
  • get_ui_url() — returns the UI’s local address, useful when scripting or when a browser doesn’t open automatically.
  • Notebook cells — the UI’s unit of work: write SQL, run it, see a results grid with inferred column types directly beneath.

Why This Matters#

Not every question is best answered by reading text output line by line — sometimes you want to scroll a result set, resize columns, or run a few related queries side by side while you think. The UI gives you that without leaving DuckDB or trading away anything the CLI and Python API already do; it’s one more way to reach the same engine, not a different tool.
