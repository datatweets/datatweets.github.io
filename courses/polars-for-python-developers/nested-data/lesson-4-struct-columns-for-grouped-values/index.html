Welcome to Struct Columns for Grouped Values#

Lessons 2 and 3 worked with a struct column that arrived already nested, read straight out of thistlewood_orders_nested.json. This lesson builds a struct column the other way around: starting from separate, existing columns and bundling them together with pl.struct(). It’s the same dtype either way – a struct column read from JSON and a struct column built by hand from pl.struct() behave identically once they exist.

By the end of this lesson, you will be able to:

  • Use pl.struct([...]) to bundle two or more existing columns into one struct column
  • Read a field back out of a hand-built struct column with .struct.field()
  • Use pl.struct() inside a group_by().agg() to bundle multiple aggregation results into one struct
  • Use .unnest() to expand a struct column back into separate columns

The original city and state columns are still there too; pl.struct() doesn’t consume its inputs, it copies them into a new bundled column alongside them.

pl.struct() isn’t limited to bundling existing columns – it can bundle the results of several aggregations, inside a group_by().agg(), into one struct column per group. Expanding a Struct Back Out with unnest()#

Bundling into a struct is often a means to an end – a single column that’s easier to pass around a pipeline – and .unnest() reverses it, expanding every field back into its own column:

Same values as order_stats.n_orders, .min_items, and .max_items above, now as three plain columns instead of one struct – .unnest() is the direct inverse of the pl.struct() this lesson used to build order_stats in the first place.

Practice Exercises#

Exercise 1: Bundle a min/max/avg price struct by category#

Using thistlewood_products.csv, group_by("category") and build one struct per category with pl.struct(pl.col("unit_price").min().alias("min_price"), pl.col("unit_price").max().alias("max_price"), pl.col("unit_price").mean().round(2).alias("avg_price")). Confirm the result has 8 rows (Thistlewood’s 8 categories), and print the struct for "Furniture".

Exercise 2: Confirm unnest() and the original columns produce the same values#

Take with_address from this lesson’s first section and unnest address back into city_2/state_2 (rename to avoid a collision with the originals: with_address.unnest("address") would normally just recreate city/state, so instead select and rename first). Confirm every unnested value matches the original city/state column exactly, across all 180 customers.

Hint

with_address.select("customer_id", pl.col("address").struct.field("city").alias("city_2"), pl.col("address").struct.field("state").alias("state_2")) gets you the renamed columns without an unnest naming collision – then join back to customers on customer_id and compare.

Summary#

pl.struct(["city", "state"]) bundled two existing Thistlewood customer columns into one address struct, with .struct.field("city") reading a value back out of it. pl.struct() inside group_by().agg() went further, bundling three separate aggregation results – n_orders, min_items, max_items – into one order_stats struct per customer, computed directly from this module’s own nested order data: C0001 placed 6 Q1 2024 orders ranging from 1 to 4 line items, and 167 of Thistlewood’s 180 customers placed more than one order in that same quarter. .unnest() reversed the bundle, expanding order_stats back into three plain columns with identical values.

Key Concepts#

  • pl.struct([...]) bundles existing columns without consuming them – city and state stayed in the DataFrame alongside the new address struct that bundled them.
  • pl.struct() works inside group_by().agg() just as well as in with_columns() – bundling several aggregation results into one struct per group is the same operation as bundling several plain columns.
  • You can filter on a struct field without unnesting first – pl.col("order_stats").struct.field("n_orders") > 1 reached inside the struct directly.
  • .unnest() is the inverse of pl.struct() – expanding a struct column back into separate columns recovers exactly the values that went in.

Why This Matters#

Bundling related values into one struct column keeps a pipeline’s shape simpler – one order_stats column instead of three separate ones traveling together through every later step – without losing the ability to read any individual field back out when you need it. The 167-of-180 customer count this lesson surfaced is also a reminder that a struct-based aggregation isn’t just a structural convenience: it’s checkable business data, filterable the same way any other column would be.
