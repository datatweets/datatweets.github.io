Welcome to Selecting Columns with pl.col#

Lesson 1 used pl.col("unit_price") without stopping to cover the full vocabulary. pl.col is the single most common piece of every expression you’ll write for the rest of this course, and it has several forms beyond “one column by name.” This lesson runs every one of them against the 7-column Thistlewood product catalog and confirms exactly which columns come back.

By the end of this lesson, you will be able to:

  • Select a single column with pl.col("name")
  • Select several named columns at once with pl.col("a", "b", "c")
  • Select columns matching a regex pattern with pl.col("^pattern$")
  • Select every column with pl.all(), and every column except some with pl.exclude(...)

A Single Column: pl.col("name")#

The simplest form takes one column name and returns exactly that column, wrapped as a one-column DataFrame when used inside .select():

products["product_name"] from Module 2 pulled the same column back as a Series; products.select(pl.col("product_name")) pulls it back as a one-column DataFrame instead — the same data, a different container, and the form every later expression in this course needs, since .select() and .with_columns() only accept expressions, not plain Series.

Several Columns at Once: pl.col("a", "b", "c")#

Pass more than one name, and pl.col selects all of them together, in the order given:

One pl.col(...) call, three names — a single expression that resolves to three columns, in exactly the order you asked for, regardless of the order those columns happen to sit in inside products itself.

A Regex Pattern: pl.col("^pattern$")#

When column names share a naming pattern, pl.col accepts a regular expression instead of listing every name by hand — Polars recognizes a string wrapped in ^...$ as a regex rather than a literal column name:

"^product.*$" matches any column name that starts with product — in the catalog, that’s exactly product_id and product_name, and nothing else (category, unit_price, cost, supplier, and subcategory don’t start with product, so none of them match). This is useful once a table has a family of related columns — a price_2024, price_2025 pair, or a set of flag_* boolean columns — that you’d rather select as a group than type out individually.

Everything: pl.all()#

pl.all() is the “select every column” expression — useful mainly as a starting point you then reshape, rather than as an end in itself:

products.select(pl.all()) produces a DataFrame identical in columns and shape to products itself — on its own this doesn’t do much, but pl.all() becomes useful once you start applying a transformation to every column at once (a pattern later modules use for things like casting every string column or checking every column for nulls in one pass).

Everything Except Some: pl.exclude(...)#

pl.exclude is pl.all()’s inverse — every column except the ones you name:

pl.exclude("supplier", "subcategory") returns the other five columns, in their original order, with supplier and subcategory dropped — the same net effect as listing the five you wanted with pl.col(...), but often shorter and clearer when you want “most of the table minus a couple of columns” rather than “these specific few.”

pl.exclude also works inside pl.col

pl.exclude(...) used alone (as above) means “every column except these.” You’ll also see the pattern pl.col(pl.Float64).exclude("cost") later in this course — “every column of a given dtype, except this one” — which combines column selection with a dtype filter. This lesson only needed the standalone form to make the point.

Practice Exercises#

Exercise 1: A regex on a different table#

Read thistlewood_orders_flat.csv and select every column whose name contains "price" anywhere in it, using a regex pattern with pl.col(...) (hint: .*price.* matched anywhere in the name doesn’t need the ^/$ anchors this lesson’s example used, since you’re not anchoring to the start and end). Print the matching column names and confirm they’re the ones you expect from this table’s 8 columns.

Exercise 2: Combine all() and exclude in one script#

Using products, select pl.all() into one DataFrame and pl.exclude("product_id") into another. Print both .shapes and confirm the second one has exactly one fewer column than the first, with product_id missing from its .columns.

Hint

pl.exclude(...) still returns the columns it doesn’t exclude — check the difference by comparing set(first.columns) - set(second.columns), which should contain exactly {"product_id"}.

Summary#

pl.col has broad range beyond a single name: pl.col("a", "b", "c") for several columns at once, pl.col("^pattern$") for a regex match (verified against the catalog — "^product.*$" matched exactly product_id and product_name, nothing else), plus its two close relatives pl.all() (every column) and pl.exclude(...) (every column except the ones named). All five forms are still just expressions, resolved the moment they’re handed to .select().

Key Concepts#

  • pl.col("a", "b", "c") — selects several named columns at once, in the order given.
  • pl.col("^pattern$") — a string anchored with ^...$ is interpreted as a regex, matching any column name it fits.
  • pl.all() / pl.exclude(...) — every column, or every column except the ones named; complementary shortcuts to listing columns individually.

Why This Matters#

Tables often have more columns than you want to type out by hand, and a growing table (a new price_2026 column added next year, say) shouldn’t force you to go back and edit every place you selected columns by an exhaustive list. Regex selection and pl.exclude both describe a rule about which columns to include rather than a fixed list, so code written against them keeps working as the table’s shape evolves.
