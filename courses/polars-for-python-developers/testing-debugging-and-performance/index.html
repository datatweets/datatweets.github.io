Testing, Debugging, and Performance

Write pytest tests for a Polars transformation, debug a verified 12x query-plan bug and two other gotchas, benchmark honestly with time.perf_counter, read multi-join query plans, and try streaming execution.

Every earlier module in this course ended a guided project by checking a result against a number already proven correct. This module makes that habit explicit and repeatable: instead of eyeballing output and moving on, you write tests that keep checking it for you, learn a process for tracking down a wrong answer instead of guessing at fixes, and measure performance with real numbers instead of folklore.

Lesson 1 takes clean_orders() – Module 4’s cleaning function, reused unchanged all the way through the capstone – and writes pytest tests against it, using pytest’s own programmatic API so you see its actual output, not a description of what tests “would” show. Lesson 2 turns Module 10 Lesson 5’s verified pre_partition_hive bug (a lazy group_by() on a hive-partitioned scan that silently overcounted revenue 12×) into a worked debugging process – compare against a known total, read .explain(), isolate the smallest reproducible case – and adds two more verified gotchas along the way. Lesson 3 benchmarks with time.perf_counter(), multiple runs, and a median, honestly reporting what turns out to be a dramatic difference in one comparison and a near-tie in another. Lesson 4 goes deeper into .explain() across a query with two joins and an aggregate, reading which filters pushed all the way down to a scan and which couldn’t. Lesson 5 tries engine="streaming" against engine="in-memory" and reports honestly that Thistlewood’s data is too small to show a dramatic difference, while still confirming the two engines agree exactly.

Lesson 6’s guided project pulls all of it together: a small pipeline function gets a test suite, a debugging checklist, and a benchmark, verified against the $9,195,043.62 grand total this course has now reconciled to since Module 7.

Start with Lesson 1, and put this course’s oldest habit – verify before you trust – into code that keeps verifying for you.

Lessons in this module

1 Writing Tests for Polars Transformations pytest tests for clean_orders(), Module 4's cleaning function -- run with pytest's own programmatic API so you see actual test output, covering both a transformation's shape and its values. 2 Debugging Query Behavior and Common Gotchas A repeatable debugging process -- reconcile to a known total, read .explain(), isolate the smallest repro -- applied to Module 10's verified pre_partition_hive bug plus two more common Polars gotchas. 3 Measuring and Comparing Performance time.perf_counter()-based benchmarking, run multiple times with a median, comparing a Python loop against group_by() and eager against lazy execution on the full two-year Thistlewood dataset. 4 Reading Query Plans in Depth Read a .explain() plan across two joins and an aggregation -- see a filter push all the way back through both joins to its source scan, and another filter that structurally cannot push down at all. 5 Streaming and Out-of-Core Execution collect(engine="streaming") vs engine="in-memory") on Thistlewood's order history -- confirmed identical results, and a measured timing showing streaming isn't automatically faster on data this small. 6 Guided Project: A Tested, Benchmarked Pipeline One monthly-channel revenue pipeline gets a pytest suite, a debugging checklist, and a time.perf_counter() benchmark -- closing this module the way every guided project in this course reconciles to a number already proven.
