Welcome to What Is a Series?#

Every DataFrame you’ve read or built so far in this course is made of something smaller: a Series, Polars’s name for a single, named, typed column of data. You’ve been looking at Series the whole time without naming them — every column in products.head(3) from Module 1 was one. This lesson stops and looks at a Series on its own, before Lesson 2 puts several of them back together into a DataFrame.

By the end of this lesson, you will be able to:

  • Construct a pl.Series from a plain Python list and explain what Polars inferred about it
  • Describe what a Series’s name and dtype are, and why both are set once, at construction
  • Pull a Series out of a Thistlewood Goods table and run its aggregate methods on it (.sum(), .mean(), .min(), .max())
  • Index a Series by position, and explain what happens when the position doesn’t exist

Make sure your Module 1 project is set up and Polars is installed — every code block below runs against the same Thistlewood Goods data you’ve already used.

A Series Is One Named, Typed Column#

A Series is Polars’s smallest data structure: a single column, with a name and a single dtype (data type), holding one value per position. Build one directly from a plain Python list to see exactly what that means:

Two arguments went in — a name, "unit_price", and a list of four numbers — and the printed Series shows exactly those two things back: the name ('unit_price'), the dtype Polars inferred (f64, Polars’s short name for 64-bit float), and the four values themselves. shape: (4,) is a one-element tuple, not the two-element (rows, columns) shape you’ll see on a DataFrame in Lesson 2 — a Series is one-dimensional by definition, so there’s no separate “column count” to report.

Dtype Inference from Python Types#

Polars looks at the Python values you hand it and picks a dtype without you specifying one:

Whole numbers become Int64, decimals become Float64, text becomes String, and True/False become Boolean — the same inference pl.read_csv used in Module 1 to turn unit_price into a float column without you writing a single type annotation.

Every value in a Series shares one dtype

A Series is strict about this: every value in it has the same dtype, chosen once at construction. Mixing whole numbers and decimals in the same Python list ([1, 2, 3.5]) isn’t automatically smoothed over the way you might expect — depending on how you construct it, Polars either upcasts everything to match or raises an error rather than guess. You’ll build DataFrames the safer way — one Python type per column — throughout this course, so this rarely comes up in practice, but it’s worth knowing a Series’s dtype is a real constraint, not a loose label.

A Series Pulled from a Table#

Small hand-written lists are fine for seeing the idea, but every Series you’ll work with in this course comes out of a table. Pull the unit_price column straight out of Thistlewood Goods’ product catalog:

products["unit_price"] — square-bracket indexing with a column name — is how you pull a single column out of a DataFrame, and what comes back is a polars.series.series.Series, not a plain Python list and not a one-column DataFrame. It’s Float64, matching what you’d expect for a price column, and it has 60 values — one per product in Thistlewood’s catalog.

Aggregate Methods, Built In#

A Series carries summary methods directly on it — no group_by, no expression needed, because there’s nothing to group yet:

These numbers come straight from the 60-product catalog: if Thistlewood sold exactly one of every product, that’s $13,014.81; the average unit price across the catalog is $216.91; and prices range from a $9.99 item up to a $447.66 one. .sum(), .mean(), .min(), and .max() all work the same way — no arguments, one number back — because a Series only ever has one column’s worth of values to summarize.

Positional Indexing#

A Series has no row labels (Lesson 5 covers exactly what that means for a full DataFrame), so indexing it is always by position — the same rule a plain Python list follows:

unit_price[0] is the first value in the Series, in whatever order the CSV rows happened to be in — not “the row labeled 0,” because there is no such label, just a position. Negative indices count from the end exactly like a Python list: [-1] is the last value.

Ask for a position that doesn’t exist, and Polars raises an ordinary Python exception rather than silently returning something like None:

IndexError — the exact same exception type a plain Python list raises for the same mistake, with a message that tells you precisely what went wrong: the Series only has 60 values, so position 1000 doesn’t exist.

Practice Exercises#

Exercise 1: A Series from a different column#

Using the same products DataFrame, pull out the cost column as a Series (products["cost"]) and print its dtype, .mean(), and .max(). Is the most expensive product to make (.max() on cost) the same product as the most expensive to sell (.max() on unit_price)? You’d need to look at the full row to be sure — this exercise only asks about the two Series’ maximum values, not which product they belong to.

Exercise 2: Explain the dtype#

Construct pl.Series("quantity", [1, 2, 1, 3, 5]) and print its .dtype. Then construct pl.Series("discount_pct", [10, 15, 20]) (whole-number percentages) and print its dtype too. Both lists contain only whole numbers — why might a production Thistlewood dataset still want discount_pct stored as a float instead, even though every value you’ve seen so far is a whole number?

Hint

Think about what a future value in that column might need to be, not just the values already present. discount_pct might need to represent something like 12.5% someday, even if every promotion so far happens to land on a round number.

Summary#

A pl.Series is Polars’s smallest data structure: one name, one dtype, one value per position, no row labels. You built one from a plain Python list, watched Polars infer a dtype from four different Python types, then pulled a 60-value Series out of Thistlewood Goods’ product catalog and ran aggregate methods on it — a $13,014.81 total catalog value, a $216.91 average price, and a $9.99–$447.66 range. Indexing a Series is always positional, and asking for a position that doesn’t exist raises an IndexError, the same way a plain Python list would.

Key Concepts#

  • Series — a single, named, typed, one-dimensional column of values; the building block every DataFrame column is made of.
  • dtype inference — Polars chooses a Series’s dtype from the Python values you construct it with (int → Int64, float → Float64, str → String, bool → Boolean).
  • Positional indexing — a Series has no row labels, so series[i] always means “the value at position i,” identical to plain Python list indexing, including negative indices and an IndexError on an out-of-range position.

Why This Matters#

Every schema question, every null-handling decision, and every “why doesn’t this DataFrame have an index” question the rest of this module answers comes down to how a Series behaves — because a DataFrame is nothing more than several same-length Series lined up together. Understanding a Series in isolation first makes everything that follows a straightforward extension, not a new set of rules to memorize.
