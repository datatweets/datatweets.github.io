Welcome to What Is a DataFrame?#

Lesson 1 built a single Series. This lesson builds a DataFrame the same way, directly from Series, so the relationship between the two is concrete rather than assumed. Then it inspects a Thistlewood Goods table structurally — its shape, its column names, its dtypes — and contrasts that structure, briefly and accurately, with how pandas represents the same thing.

By the end of this lesson, you will be able to:

  • Explain a DataFrame as a set of same-length Series placed side by side, with no row index
  • Build a DataFrame directly from a list of Series and explain what happens if their lengths don’t match
  • Inspect a DataFrame’s .shape, .columns, and .dtypes
  • State the one concrete, verified difference between a Polars DataFrame’s row identity and a pandas DataFrame’s

A DataFrame Is Same-Length Series, Side by Side#

Start with three Series, each already the same length — three product IDs, three names, three prices:

That printed table, products, is a pl.DataFrame — and every one of its seven columns (product_id, product_name, category, subcategory, unit_price, cost, supplier) is a Series, exactly like the ones you built by hand in Lesson 1, just read from a CSV instead of typed out as a list.

Building One Directly from Series#

To see the relationship without a CSV in the way, build a small DataFrame straight from three Series objects:

pl.DataFrame([product_id, product_name, price]) takes a list of Series and lines them up as columns, in the order given. Each Series keeps its own name (that’s where the column headers product_id, product_name, price came from) and its own dtype (that’s where str, str, f64 came from). Nothing else is needed — a DataFrame doesn’t add any structure a set of same-length Series didn’t already have.

What “Same-Length” Enforces#

The word “same-length” isn’t a suggestion. Build a fourth Series with the wrong number of values, and try the same construction:

A ShapeError is raised immediately, naming exactly which column disagreed and by how much. There’s no silent padding with nulls, no silent truncation of the longer columns — a DataFrame’s columns being the same length is a hard invariant, not a best-effort convenience.

Inspecting a DataFrame’s Structure#

Back to the products table — three quick structural checks you’ll reach for constantly for the rest of this course:

.shape is a (rows, columns) tuple — 60 products, 7 columns — the two-dimensional counterpart to a Series’s one-element shape: (n,) from Lesson 1. .columns is a plain Python list of column names, in order. .dtypes is a plain list of dtypes, in the same order as .columns — position i of .dtypes describes position i of .columns. (Lesson 4 introduces .schema, which pairs names and dtypes together into one structure instead of two parallel lists — useful when you want both at once.)

Selecting a Column Returns a Series, Not a Special Axis#

One more concrete consequence of “a DataFrame is Series side by side”: pulling a column back out returns a Series, with all the Series behavior from Lesson 1 intact:

catalog_sample["price"] is a polars.series.series.Series, and .sum() on it works exactly the way it did on unit_price in Lesson 1 — because it’s the exact same kind of object, whether it came from a hand-built list of Series or straight out of a CSV.

A Brief, Accurate Contrast with pandas#

Module 1 showed a real pandas bug rooted in chained indexing and copy/view ambiguity — that’s a correctness story, not a structural one, and it isn’t repeated here. The structural difference worth naming plainly: a pandas DataFrame carries a row index as part of its identity, visible by default every time you print one.

Notice the unlabeled leftmost column: 0, 1, 2 — that’s products_pd’s RangeIndex, printed by default alongside the actual data every single time. Compare that with catalog_sample above (the identical data, as a Polars DataFrame): no such column appears, because a Polars DataFrame simply doesn’t carry one. This is purely structural, not a claim about correctness or speed — Lesson 5 goes deep on what follows from a Polars DataFrame having no index at all.

Practice Exercises#

Exercise 1: Build one from four Series#

Using Lesson 1’s unit_price Series (products["unit_price"]) alongside three more columns you pull the same way — products["product_id"], products["category"], products["supplier"] — build a new DataFrame with pl.DataFrame([...]) containing just those four columns. Print its .shape and confirm it’s (60, 4).

Exercise 2: Trigger the ShapeError yourself#

Slice one of the four Series from Exercise 1 down to a shorter length (e.g., products["supplier"][:10], which keeps only the first 10 values) and try building the same four-column DataFrame again. Confirm you get a ShapeError, and read the message carefully — which column does it name, and does that match which one you shortened?

Hint

Series slicing works the same as the positional indexing from Lesson 1 — series[:10] is the first 10 values by position, no different from slicing a plain Python list.

Summary#

A pl.DataFrame is a set of same-length Series lined up as columns, nothing more — you built one directly from three Series, watched a fourth mismatched-length Series raise a ShapeError immediately, and inspected a 60-row, 7-column Thistlewood products table’s .shape, .columns, and .dtypes. Selecting a column back out always returns a Series, with every method from Lesson 1 intact. Structurally, the one concrete difference from pandas worth naming here is the row index pandas prints by default and Polars simply doesn’t have — a fact, not yet an argument for why it matters, which Lesson 5 makes in full.

Key Concepts#

  • DataFrame — a set of same-length Series placed side by side as columns; a ShapeError is raised immediately if the lengths don’t match.
  • .shape — a (rows, columns) tuple describing a DataFrame’s size, the two-dimensional counterpart to a Series’s one-element shape.
  • .columns / .dtypes — parallel lists of column names and their dtypes, in the same order.

Why This Matters#

Knowing that a DataFrame is only same-length Series — no hidden index, no extra bookkeeping structure — makes every later operation predictable. When Lesson 3 builds DataFrames from dictionaries and records instead of Series directly, and when Module 3 starts transforming columns with expressions, you’re not learning new rules about what a DataFrame secretly contains; you’re just building the same simple structure through different front doors.

Continue Building Your Skills#

You’ve built a DataFrame from Series directly. Lesson 3 covers the ways you’ll construct one most of the time in practice: a dictionary of columns, a list of row-records, and an explicit schema when you want to control the dtypes yourself.
