# Docker & Kubernetes for Data Engineering — Image Provenance Registry

Every image referenced by a lesson under `content/courses/docker-kubernetes-for-data/`
must have an entry here — same rule as `assets/images/blog/PROVENANCE.md`, extended
with capture provenance since most images in this course are real screenshots of
live local state (Docker Desktop, the Kubernetes Dashboard), not hand-authored
diagrams. A screenshot's whole value is that it's real; this table is what makes
that claim checkable and lets anyone reproduce the exact state and re-capture it.

Allowed image types:
- `original-diagram` — hand-authored SVG, house style, via `blog-pipeline/render_svg.py`
  (checked against `blog-pipeline/IMAGE_QA_CHECKLIST.md`).
- `docker-desktop-screenshot` — real capture via `course-pipeline/capture_docker_desktop.py`.
- `k8s-dashboard-screenshot` — real capture via `course-pipeline/capture_k8s_dashboard.py`.
- `cli-output` — not an image; verified terminal text pasted directly into the
  lesson (the default for anything without a real GUI — see `DATA_ENGINEERING_BLUEPRINT.md`
  Course 3's note on when a screenshot is/isn't warranted). Not registered here since
  it's not a file, listed only for completeness.
