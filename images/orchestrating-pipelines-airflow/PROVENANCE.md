# Orchestrating Data Pipelines with Airflow — Image Provenance Registry

Every image referenced by a lesson under `content/courses/orchestrating-pipelines-airflow/`
must have an entry here — same rule as `assets/images/blog/PROVENANCE.md` and
`static/images/docker-kubernetes-for-data/PROVENANCE.md`, extended with capture
provenance for real screenshots. A screenshot's whole value is that it's real;
this table is what makes that claim checkable and lets anyone reproduce the
exact state and re-capture it.

Allowed image types:
- `original-diagram` — hand-authored SVG, house style, via `blog-pipeline/render_svg.py`
  (checked against `blog-pipeline/IMAGE_QA_CHECKLIST.md`).
- `airflow-ui-screenshot` — real capture via `course-pipeline/capture_airflow_ui.py`.
- `k8s-dashboard-screenshot` — real capture via `course-pipeline/capture_k8s_dashboard.py`
  (reused from the Docker & Kubernetes course, same Kind cluster/Dashboard).
- `cli-output` — not an image; verified terminal text pasted directly into the
  lesson (the default for anything without a real GUI moment).
